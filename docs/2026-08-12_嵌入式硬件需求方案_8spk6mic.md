# 嵌入式硬件需求方案 — 8 扬声器 / 6 误差麦 / 1 参考麦

> **日期**: 2026-08-12 · **阶段**: 样机 · **基线**: 当前 `gfanc-direct-weight` 代码实测数据
> **配置**: S=8 扬声器, E=6 误差麦, ref=1, L=1024, Fs_anc=16kHz, CNN 直接权重（K=S×C=8×15=120）
> **两份方案**: ① 不带反馈环路（纯前馈） ② 带反馈环路（前馈 + B-1 低频反馈增强）
> 相关: [GFANC_综合审查报告_合并版](GFANC_综合审查报告_合并版.md)（物理瓶颈/Phase 路线）、[窗户ANC可行性](窗户ANC可行性-因果限制_实测_方案.md)

## 0. 关键结论（TL;DR）

- **FxLMS 是算力绝对主力**: 前馈 **2.68 GMAC/s**（E×S=48 条路径 × L=1024，含功率归一化/leak/带通）——E×S 从当前 6 → 48（8×），算力平方级增长
- **在线 Ŝ 辨识默认开启，额外 +1.70 GMAC/s**（sec_online_mu=5e-6，非可选已计）；嵌入式可 `GFANC_SEC_MU=0` 关闭或降频更新——**决定 RK3568 余量够不够的关键开关**
- **CNN @1Hz 仅 ~0.1 GMAC/s（前馈的 ~4%）**, 且与通道数无关——"CNN 不影响降噪量"是**结构性要求**（独立核/异步调度 + 双缓冲），不是算力问题
- **带反馈环路（B-1）再叠加 ~0.6-1.2 GMAC/s** → 总 **3.4-4.0 GMAC/s（关在线Ŝ）/ 5.1-5.7（开）**
- **内存 fp32 ≈ 3.85MB**（int8 CNN 后 ≈ 2.6MB）；Flash ≈ 1.2MB
- **8spk 配置超出当前代码编译上限**（GFANC_E_MAX=5 / S_MAX=4 / SC_DW_MAX=30）——先扩上限跑通离线，再谈硬件

## 2. 算力需求（逐模块 @16kHz）

### 2.1 前馈 FxLMS（核心，两方案都要）

| 模块 | MAC/样本 | 计算 |
|---|---|---|
| 前向 anti = Wc·x | 8,192 | S×L |
| xd 更新（参考×Ŝ） | 49,152 | E×S×SEC_LEN |
| 功率归一化 Σxd² | 49,152 | E×S×L（NLMS 前置，独立全遍历，**2026-08-13 补**） |
| 梯度更新 | 49,152 | E×S×L |
| leak 衰减 + Fx/err/ref 带通 | ~11,700 | S×L + E×S×64 + E×64 + 64 |
| **小计** | **167,360** | **@16k = 2.68 GMAC/s ≈ 5.4 GFLOPs/s** |
| 在线 Ŝ 辨识（默认开） | +106,496 | S×L + 2×E×S×L → **+1.70 GMAC/s** |

实时硬约束: 16kHz 样本周期 **62.5µs** 内完成 ≥2.7G MAC（在线 Ŝ 开则 ≥4.4G）。

> 修正说明（2026-08-13 对抗性核对）: 原表只列了前向/xd/梯度三行（1.70 GMAC/s），漏了**功率归一化**（fxnlms_mimo.c:220-232 是独立 E×S×L 全遍历）与 **在线 Ŝ 辨识**（sec_online.c，默认开启）。两项都是实打实的 MAC。

### 2.2 CNN 直接权重 @1Hz

- 卷积主干 ~70 MMAC（CH=64/4残差块，**与 S/E 无关**）；线性层 64→120 仅增 ~7.7K MAC
- **平均 ~0.1 GMAC/s，占前馈 ~4%** — 算力不是问题
- **"不影响降噪量"的结构要求**（硬件必须满足）:
  1. **独立核或低优先级异步** — 绝不让 CNN 1Hz 突发（~70MMAC）与 FxLMS 共享实时核时间片
  2. **双缓冲** — CNN 计算当前 1s 期间，实时核读上一秒 Wc，零等待
  3. 突发耗时 < 1s 窗口即可（对实时路径零影响）

### 2.3 反馈抵消（两方案都必做）

- 8 扬声器对 1 参考麦的声学污染比 2spk 严重得多 → 反馈抵消**非可选**
- 算力: S×FB_LEN = 8×256 ≈ **0.03 GMAC/s**（小）

### 2.4 反馈环路 B-1（仅方案 2）

- 48 条 (e,s) 反馈控制器，无参考麦、以误差麦为源
- 算力: 3×E×S×L_fb（前向+Ŝfb+梯度），L_fb=256~512 → **0.59~1.18 GMAC/s**
- 另需 48 条 Ŝfb 测量与存储（96KB）

### 2.5 汇总

| | **方案 1 纯前馈** | **方案 2 前馈+B-1** |
|---|---|---|
| 前馈 FxLMS（含功率/leak/带通） | 2.68 | 2.68 |
| CNN @1Hz | 0.10 | 0.10 |
| 反馈抵消 | 0.03 | 0.03 |
| B-1 反馈 FxLMS | — | 0.59~1.18 |
| 在线 Ŝ 辨识（默认开，可关） | +1.70 | +1.70 |
| **持续总（在线Ŝ 关 / 开）** | **2.81 / 4.51 GMAC/s** | **3.40~3.99 / 5.10~5.69 GMAC/s** |
| **保守 2× 余量 → 需 ≥（关 / 开）** | **5.6 / 9.0 GMAC/s** | **6.8~8.0 / 10.2~11.4 GMAC/s** |

> RK3568 实测 6-8 GMAC/s → 方案1 **关在线Ŝ** 余量 ~1.1-1.4×（偏紧）；**开在线Ŝ 则 <1×，不够**。若功率归一化改滑动和（O(1)/样本），FxLMS 可回落到 ~1.9 GMAC/s，是夺回余量的最大杠杆。

## 4. 延迟要求

- **方案 1（纯前馈）**: 处理链 **<3-5ms**（前馈因果净预览 = τ_pri − τ_spk − τ_proc 转正）
- **方案 2（带 B-1）**: **环路 <2ms 硬约束**（反馈稳定带宽 ≈ 0.375/τ → 2ms 达 20-200Hz，PC 12.4ms 只有 20-30Hz，见审查报告 B-1 分析）
- 两者都需**确定性执行（裸机/RTOS）**；音频缓冲 **≤64 帧(48k)=1.3ms**
- **Linux+ALSA 附加 5-10ms → 两方案都不可用**（仅算法验证样机可接受）

## 6. 硬件方案

### 方案 1 — 纯前馈（不带反馈环路）【样机首选】

**主控: 4×Cortex-A55 @≥1.5GHz + RTOS/裸核** — RK3568 / i.MX 8M Plus

| 维度 | 评估 |
|---|---|
| 算力 | 4×A55×2 MAC/cycle×1.5GHz = 12 GMAC/s 理论；实测 ~1.5-2 GMAC/s/核 → **~6-8 GMAC/s vs 5.6 需求（关在线Ŝ），余量 1.1-1.4× 偏紧**；开在线Ŝ（9.0）→ **<1× 不够**。建议关在线Ŝ + 功率滑动和优化 |
| 内存 | 板载 DDR 满足 3.85MB 无压力 ✓ |
| 延迟 | RTOS 上 <3ms 可达；Linux 只当算法验证 |
| 软件复用 | 当前 C 代码直接交叉编译到 A55（NEON），移植量最小 |
| 成本 | 核心板 $40-80，开发板 $80-150 |
| 备选 | i.MX RT1170（M7@1GHz+M4）**不再够**——修正后 L=512 仍需 ~1.4 GMAC/s（关在线Ŝ），RT1170 实测 ~0.9-1 GMAC/s |

### 方案 2 — 带反馈环路（前馈 + B-1 低频增强）

**主控: 4×Cortex-A55 + RTOS（i.MX 8M Plus）** 或 **FPGA（Zynq-7000）**

| 路线 | 算力余量 | 延迟 | 工程成本 |
|---|---|---|---|
| **A55 RTOS**（L=512 + L_fb=256） | 需 4.8 GMAC/s；实测 ~5-6 → **1.0-1.3×，偏紧** | <2ms 需缓存/调度精调 | 软件复用好，样机迭代快 |
| **FPGA（Zynq-7000 PL）** | 48 条 (e,s) FxLMS 路径并行（220 DSP48），**任意余量** | 确定性最强 | RTL ~2-3 人月，样机慢 |

- 反馈路径: 需 **E×S=48 条 Ŝfb 测量与存储** + 出厂校准协议（ADV-E1）
- 成本: A55 板 $80-150；Zynq 板 $150-400
- **保守建议**: 样机先用 A55 RTOS 验证 B-1 收益（快）；确认 <2ms 与 6 GMAC/s 是硬需求后，量产再转 FPGA 保底

### 两方案共用

- **CNN 独立核**: 方案 1 → A55 空闲核；方案 2 → FPGA PS 或 A55 空闲核（满足"不影响降噪量"）
- **编译上限扩**: `GFANC_E_MAX` 5→8、`GFANC_S_MAX` 4→8、`SC_DW_MAX` 30→120（纯代码，先做）
- 反馈抵消必开（8spk→1ref 污染）；次级路径测量扩到 48 条（现有扫频校准工具扩展）

## 7. 决策点

1. **L = 1024 还是 512？** 省一半 FxLMS 算力（2.68→~1.4 GMAC/s 关在线Ŝ）→ 决定方案 2 能否 A55 单档（RT1170 已出局）
2. **B-1 反馈环路要不要？** 决定方案 1/2，及 <2ms 硬约束是否成立
3. **子滤波共享 or 每扬声器独立？** sub_filters 491KB vs 246KB
4. **CNN int8？** 内存 3.85→2.6MB，决定能否脱离外部 DDR
5. **48 条 Ŝ/Ŝfb 测量** = 校准工作量的最大项（8 扬声器 × 6 误差麦）
6. **在线 Ŝ 辨识保留？（2026-08-13 新增）** 当前默认开（sec_online_mu=5e-6）→ 额外 +1.70 GMAC/s，RK3568 余量从 ~1.2× 跌到 <1×。嵌入式可 `GFANC_SEC_MU=0` 关（依赖出厂 48 条 Ŝ 校准）或降频更新 —— **方案 1 能否上 RK3568 的第一开关**
7. **功率归一化改滑动和？（2026-08-13 新增）** O(1)/样本替代 E×S×L 全遍历（fxnlms_mimo.c:220-232），FxLMS 2.68→~1.9 GMAC/s —— 夺回余量的最大杠杆，需注意浮点累积漂移、定期重求和

### 9.2 音频通道（真正的坑：现成板板载仅 2ch）

**阶段 A — 算法验证（先用现有 UMC404HD，零新增音频硬件）**
- UMC404HD = 4in/4out → 只能验证当前 E=3/S=2；**8spk/6mic 需 7in/8out，通道不够 → 完整验证必须走阶段 B**
- **缓冲现实（2026-08-13 查证）**：
  - ASIO 支持 64（通常稳）和 32（≈5-6ms 往返，但 CPU 需求 +50%，极易 xrun/爆音）；128 最安全
  - **减缓冲不伤降噪，反而缩短环路延迟 → 预览预算上升 → 帮助降噪**。FxLMS 逐样本在线自适应，与块大小无关（main_realtime.c:376 每样本 tick）；真正伤降噪的是 **xrun 撕裂数据流** → FxLMS 梯度被污染 → 发散
  - 但 UMC 的 12.56ms 环路大头在界面固有 USB 往返 + codec（128 帧只占 2.67ms），128→64 仅省 1-3ms，预览预算仍深负（−10.6→~−8ms）→ **宽带对消在 UMC 上物理做不到**，只能纯音/周期验证（250Hz 实机 17dB）
  - ⚠ **改 GFANC_BUFFER 后必须重跑 `calibrate_secondary` 更新 `sec_bulk_delay.bin`**（main_realtime.c:1166-1167 注释明确），否则 Ŝ 延迟不对齐 → 相位错 → 发散

**阶段 B — RTOS 最终形态（<3ms，板级 I2S/TDM codec）**
- 2× TLV320ADC6140（4ch ADC/片 → 7ch ADC，立创商城 ~¥30-60/片）
- CS4382（8ch DAC）或 CS42448（6in/2out）~¥60-100
- 走 RK3568 I2S/TDM GPIO，需自画转接板或买带多通道 codec 的载板
- 中间可选：8in/8out USB 接口（如 UMC1820 ~¥1500）只加通道不加延迟改善，仍仅算法验证用
