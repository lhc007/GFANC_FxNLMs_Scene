# GFANC 实时 ANC 实测与窗口降噪规划 (2026-08-04)

## 摘要

本次会话解决了"参考麦不收音"的根因(模拟增益旋钮过低,非软件问题),实测得到干净基线(NR 3-6dB),
定位了 125Hz 反馈振荡(环路延迟自激)与环路延迟对宽带降噪的物理上限,并规划了面向窗户(40×115cm)
主动隔声的 DSP 方案。代码改动:次级校准支持 `GFANC_CAL_NOISE`、ANC 带通 256→64tap 砍环路延迟。

---

## 1. 灵敏度根因:UMC 输入旋钮,不是软件参数

**现象**:ECM8000 电容麦"不贴麦不收音";1 米处马路噪音 ref=-55dBFS。

**结论**:根因是 UMC404HD 输入增益旋钮太低(曾一度以为是幻象电源/线材问题,均排除)。
旋钮拧到最大后,ref 自然到 -30dBFS,自动增益回到 1x,无需任何软件补偿。

**教训**:`GFANC_MIC_GAIN=20` + `GFANC_DIVERGE_ANTI=5` 是弱信号期的**诊断兜底,已废弃**。
其中 DIVERGE_ANTI 与 mic_pre_gain 交互的机制要记牢:发散救援阈值 = `diverge_anti_rms / mic_pre_gain`,
mic_pre_gain=20 时阈值被压到 0.0125,输出一够量就被 Wc 回滚 → NR 卡死 1-3dB 爬不上去。

## 2. 旧参数在信号健康时是错的

2026-07-31 标定的 `wc_target=0.03 / step=3e-7 / wc_cold=0.5` 在信号健康时**全部失效**:

| 参数 | 健康信号下的表现 | 正确值 |
|---|---|---|
| `wc_target=0.03` | 冷启动 Wc 太热 → 开机"嗡"一声(反馈瞬态) | **0.01(默认)** |
| `step=3e-7` | Wc 过冲,antiEst 超 err 2-3 倍,peak_mute/陷波齐触发 | **1e-7(默认)** |
| `GFANC_MIC_GAIN=20` | 噪声地板/反馈同步放大 20×,削波风险 | **自动(≈1×)** |
| `GFANC_DIVERGE_ANTI=5` | 绕过输出上限,只是诊断用 | 撤掉 |

**当前工作配置 = 全部默认参数 + 旋钮最大 + 干净校准,实测 NR 稳定 3-6dB。**

## 3. 校准质量规则

- 校准时声卡 **SIG 常亮、CLIP 不亮**。CLIP = ADC 削波,发生在数据进程序前,不可逆,污染路径辨识。
- 探针响度 `GFANC_CAL_NOISE`(默认 0.9)控制,**反馈/次级两个校准都支持**(次级 2026-08-04 补上)。
  旋钮最大时默认 0.9 会削波 → 设 0.4-0.5。
- **校准和运行必须用同一旋钮位置**(路径系数嵌入模拟增益)。
- ERLE<8dB 的弱耦合路径自动置零(正常保护),失败路径每次校准可能漂移(e0,s0 或 e1,s1)。

## 4. 125Hz 反馈振荡:环路延迟自激

**机理**:扬声器反噪音 → 误差麦听到 → FxLMS 当"要消的噪音"继续消 → 正反馈环。
12.4ms 环路延迟的纯延迟反馈环,天然在 `1/(2τ)≈40Hz` 及奇次谐波(120/200Hz)起振 —— **125Hz 是 3 次谐波,延迟自己喂出来的,与外部声源无关**。

**铁证**:陷波 ON(默认阈值 12)→ 稳定 3-6dB;陷波 OFF(HW_THRESH=15)→ 周期性"收敛→err=0.7 爆炸→静音"(~1.1s)。

**结论:不要调高 `GFANC_HW_THRESH`(默认 12)。** 陷波是兜底;根治靠:
1. 误差麦旋钮降 6-10dB(砍环路增益;误差麦只需量残差,0.02 即够,不必 0.05-0.12)
2. 扬声器与误差麦拉开 30-60cm、错开朝向(砍耦合)
3. Ŝ 全路径健康(别置零)

## 5. 环路延迟 12.4ms 的构成与砍法

```
环路 12.4ms = ASIO 缓冲管线 8.4ms(128 样本@48k=2.67ms 只是部分)+ Ŝ 声学峰 4ms(物理,改不了)
其中 ANC 带通 256tap 群延迟 8ms 占用预测时间
```

| 杠杆 | 省 | 状态 |
|---|---|---|
| **带通 256→64tap** | ~6ms(8→2ms) | ✅ **2026-08-04 已改**(main.c / main_realtime.c / export_bin.py,bin 已重生成) |
| GFANC_BUFFER 128→64 | ~1.5-2ms | 可试,128 以下是爆音边界 |
| 参考麦往窗外移 1m | 预览 1.9→3ms | 物理,免费 |

砍完 64tap 后宽带上限 55→~150-200Hz;宽带公式 `f_max ≈ 1/(2×(环路−预览))`。

## 6. 几何要求(前馈 ANC 物理前提)

```
音响(噪声源) → 参考麦(ch0) → [ANC扬声器 + 误差麦 = 安静区]
```

- 参考麦要**先听到、且听到的 ≥ 误差麦**(err/ref ≤ ~1);音响放反侧(靠近误差麦)会 NR 掉一半。
- ANC 扬声器靠近误差麦那侧(抵消作用点),但别怼着麦。
- 误差麦旁说话/拍手会触发静音保护 —— 正常,误差麦是安静区目标,不是测试拾音器。
- 误差麦是过定(E>S)系统里的"便宜采样",扬声器是"贵的成形资源" —— 车/航空几十年结论:空间降噪用 E>S。

## 9. 窗口主动隔声规划(40×115cm,马路噪音 20-800Hz)

**通道需求(整窗 p≈0,按 λ/2 空间采样):**

| 频段 | 单元数(扬声器+误差麦) |
|---|---|
| 20-300Hz | 2-3 |
| 20-400Hz | 3 |
| 20-500Hz | 8 |
| 20-800Hz | **12**(2 宽 × 6 高) |

**延迟需求**:800Hz 宽带要 `环路−预览 < 0.625ms` → 环路 < ~2.5ms(参考麦窗外 1m 时预览 3ms)。

**DSP 可行性**:12×12 MIMO @16kHz ≈ 1.2 GMAC/s。
- ADAU1461(SHARC,~1.5 GMAC/s)刚好,控制率跑 16kHz
- TI C66x(4-8 GMAC/s)富余
- **关键坑:通用音频 codec 延迟 1-2ms 会吃光预算,必须 ANC 级低延迟 codec**(ADAU1787 或高速 ADC/DAC + 逐样本中断)

**结论:8 通道只到 ~500Hz;800Hz 需要 12 通道 + 低延迟 codec + SHARC/C66x。FPGA 非必需。**

## 10. 算法优化与延迟验证 (2026-08-05)

### 10.1 实时天花板诊断

- **PC 实时稳定 NR 仅 4-6dB,人耳听不到可闻降噪**(误差麦处) —— 但这是 12.5ms 环路的结构性限制,不是算法问题。
- **NR_est 不可信**:依赖 Ŝ 模型 + 误差麦灵敏度,误差麦降太狠时读数落在地板、NR 虚高。**唯一真值是离线 NR_true(Pri 模型已知真值)。**
- 离线 13dB(无延迟)证明算法/模型没问题;差距全在"实时声学环境:延迟 + 反馈"。

### 10.2 三个算法改动(2026-08-05)

| 改动 | 文件 | 效果 |
|---|---|---|
| **leak 默认 5e-6→5e-7** | gfanc_types.h | 弱信号下 leak 压死 Wc 生长,降一档让 Wc 长起来(收敛杠杆) |
| **变步长 VS-LMS** | fxnlms_mimo.c/.h | 双 EMA 尖峰检测:误差相对基线跳变→降步防反馈过冲,平滑收敛全速。**解开"step 高→振荡,低→慢"死结** |
| **虚拟延迟/预览** | main.c | `GFANC_VIRT_DELAY_MS`(DSP 延迟,加 Ŝ)、`GFANC_VIRT_PREVIEW_MS`(参考→误差声学距离,加 Pri),离线验证因果性 |

### 10.3 关键验证结果

**实时(硬件调整后):** 默认 NR 4.4→**6.2dB**;step=3e-7/5e-7 从"振荡+7次MUTE"变为**稳定(MUTE=0)** —— VS-LMS 达到设计目标。

**离线虚拟延迟扫描(窗口场景,预览 3ms):**

| 环路延迟 | NR | 结论 |
|---|---|---|
| ≤2ms(DSP 目标) | **~15dB** | ✅ 宽带因果成立,算法全能力 |
| 3ms | 12.4dB | 因果边缘 |
| 5ms | 7.1dB | 宽带断,只剩周期 |
| PC 12.5ms | ~6dB | 印证实时实测 4-6dB |

**核心结论:算法在 ≤2ms 延迟 + ≥3ms 预览(参考麦窗外 1m)下能到 ~15dB。2ms DSP 是硬件目标,与算法能力匹配。** 实时 NR_est 不应作为效果证明,离线 NR_true 才是。
