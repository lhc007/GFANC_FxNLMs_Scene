## 〇、已尝试但放弃的方向

### F-A: 实时 FxNLMS 信号结构

**目标**：用实测误差直接驱动 LMS 梯度（而非离线式的合成误差）

**设计本身正确**：`fxnlms_tick_rt`（anti_out = Wc ⊗ ref，ΔWc = -μ × err_meas × Fx）
是标准 Filtered-x LMS 的实时形式，商业 ANC 均采用此结构。

**当前为何失败**：F-B 提供的实测 Sec 含 73ms USB 缓冲延迟 → `err_meas` 与 `Xd` 时域
完全错位 → LMS 梯度方向随机 → Wc 瞬间发散。**根因在 F-B（Sec 模型错误），不在 F-A。**

**何时重新启用**：换共时钟多通道声卡后，F-B 可测得正确的声学路径（~0.3ms），
F-A 即可正常工作。恢复方法：`git revert 162d357`。
**当前已回退，代码在 git 历史中保留。**

### F-B: 次级路径实测校准

**目标**：用实测冲激响应替代仿真数据

**设计本身正确**：实测次级路径比仿真数据更准确，是 ANC 系统校准的标准做法。

**当前为何失败**：两个独立 USB 设备（YDM6MIC + USB Audio）的 I/O 缓冲延迟每次都不同
（实测 73ms，jitter 几十 ms）。离线测量值在下次运行时已失效——这不是测量方法的错，
是硬件架构的物理限制。

**何时重新启用**：换共时钟多通道声卡后，同一时钟驱动所有 ADC/DAC，
I/O 延迟固定 → 离线测量值每次一致 → F-B 生效 → 连带修复 F-A。
恢复方法：`git revert 162d357`。

**当前替代方案**：`data/secondary_path.bin`（仅含声学路径）+ `DSP_DELAY=16`。
在独立 USB 设备上已足够，NR 4-9dB 证明系统正常工作。

## 一、已知问题与根因

### 1.1 扬声器输出音量不足

**现象**：播放马路噪声（~70 dB SPL）时，扬声器反噪声几乎听不到。

**根因**：YDM6MIC 麦克风灵敏度为 **-26 dBFS @ 94 dB SPL**。这意味着：

| 声压级 (SPL) | 场景 | 数字输出 (float32) |
|-------------|------|-------------------|
| 120 dB | 声学过载点 | 1.0 (满幅) |
| 94 dB | 摩托车近距 | 0.05 |
| 70 dB | 马路噪声 | 0.003 |
| 40 dB | 安静房间 | 0.0001 |

**代码实际状态**：

已实现可调输入预增益 `MIC_PRE_GAIN=10x`（`main_realtime.c:29`），ref 和 err 通道均已应用。
反馈抵消（P0）完成后，10x 增益可稳定运行，无啸叫。
Wc 构造使用自动 RMS 归一化（`scene_controller.c:99`）。

**FxNLMS 的自动补偿**：

功率归一化 LMS 对小信号有内在补偿：`ΔWc = -μ × err × xd / power`。低输入时 power 小，有效步长自动放大。
MIC_PRE_GAIN 同时放大参考和误差信号，稳态 anti_out 由误差麦处的实际声学噪声决定，不随增益线性变化。

**真正的瓶颈**：
1. **麦克风灵敏度**（-26 dBFS @ 94dB SPL）：YDM6MIC 是主要限制。即使噪声源覆盖全部麦克风，
   数字信号仍微弱（ch0≈0.001），需要硬件前置放大器将信号抬升 20-40dB
2. **声学解相关**（见 1.3 节）：噪声源必须同时覆盖参考麦和误差麦，否则 ANC 不触发或效果差
3. 扬声器最大 SPL：DAC 满幅 ±1.0 是硬天花板
3. 麦克风自噪声：系统残差底噪约 0.0003 (~50 dB SPL)，数字增益无法改善

**解决方向**：
1. **反馈抵消（P0）**——优先级最高的软件项，做成后可安全提升增益到 20-50x
2. **硬件前置放大器**——20-40 dB 模拟增益，改善 SNR
3. **扬声器功放**——增大驱动功率
4. **更换麦克风**——高灵敏度 ANC 麦克风

### 1.2 声反馈（啸叫）

**现象**：增益过大时扬声器输出被参考麦拾取，形成正反馈环路。

**根因**：前馈 ANC 的固有缺陷——参考麦和扬声器之间缺乏物理隔离。

**当前缓解措施**：
- 输出限幅 ±1.0
- 反馈检测（全通道 RMS 相近时自动降增益）
- 安全静音（err > ref 时 MUTE）

**解决方向**：
1. **反馈路径建模与抵消**——测量扬声器→参考麦传递函数，从参考信号中减去
2. **物理隔离**——参考麦朝外、扬声器朝内，中间加物理屏障（耳机 ANC 标准做法）
3. **自适应反馈抵消**——额外自适应滤波器实时估计并消除反馈分量

### 1.3 开放空间声学解相关

**现象**：离线测试 NR=15dB，但实时开放空间中 NR 仅 2-3dB（外部噪声下）。

**根因**：离线测试中参考信号和误差信号经过同一初级路径，相关度 100%。
真实房间中，噪声经墙壁反射、混响后到达误差麦，与参考麦采集的直达声**部分不相关**。
LMS 无法抵消不相关的噪声分量。这是前馈 ANC 在开放空间的物理极限，非算法缺陷。

**验证**：离线 `main.exe` 仍保持 15dB → 算法未退化，瓶颈在声学环境。

**解决方案**：
1. **窗户 ANC 配置（推荐实验）**——参考麦伸窗外，扬声器+误差麦在窗内侧。
   噪声从窗户进入的路径确定，解相关程度远低于全室内反射 → 预期 NR 10-15dB
2. **多通道参考**——利用 YDM6MIC 的 6 个麦克风做波束成形，提取直达声分量
3. **反馈 ANC 辅助回路**——用误差麦自身信号做反馈控制，不依赖参考麦相关性

### 详解

#### P0: 反馈抵消 ✅ 已完成

**实现**：`src/calibrate_feedback.c` + `main_realtime.c`

1. **校准程序** (`calibrate_feedback.exe`)：扬声器播放 4 秒白噪声，参考麦录制，
   NLMS 辨识 256 tap FIR → 存入 `data/feedback_path.bin`
2. **运行时**：每样本 `ref_corrected = ref_raw - Fb_path ⊗ anti_output`，
   反馈 FIR 的输出抵消扬声器漏回参考麦的分量
3. **自动降级**：若 `feedback_path.bin` 不存在，自动禁用，不影响正常 ANC

**实测效果**：
- 反馈路径：peak @ tap 7 (0.44ms ≈ 15cm)，衰减约 -34dB
- 10x 增益稳定运行（之前无抵消时 6x 即振荡）
- 15x 增益在噪声源良好耦合时 anti 削波（>0.5 RMS），证明 ANC 算法有效但需适度增益
- 反馈抵消量 RMS ~0.0001-0.0015（取决于 anti 幅度）
- 当前核心瓶颈：麦克风灵敏度 + 声学解相关 (见 1.3 节)

#### P1: 增益标定

**现状**：MIC_PRE_GAIN 已实现且可调，但最优值仍需手动试凑。换硬件后需要重新调整。

**方案**：
1. 启动时播放粉红噪声 @ -12 dBFS
2. 参考麦录制 1 秒，测量 RMS
3. 计算预增益：`pre_gain = target_rms / measured_rms`
4. 存入配置文件，即插即用

**预期收益**：换硬件零配置，但当前 5x 上限由反馈环路决定，标定本身不能突破这一限制。

#### P1: 窗户 ANC 实验配置

**背景**：实测发现开放空间中参考麦和误差麦的声学解相关是 NR 的主要瓶颈（NR 仅 2-3dB
vs 离线 15dB）。噪声经墙壁反射/混响到达误差麦的分量与参考麦采集的直达声不相关，
LMS 无法抵消。将参考麦置于噪声源侧（室外）、扬声器和误差麦置于受保护侧（室内窗户
平面），可最大化参考-误差相关性。

**实验方案**：
1. 参考麦伸出窗外，朝外采集马路噪声直达声
2. 扬声器对准窗户中心，朝室内发射反噪声
3. 误差麦在窗户内侧 10-20cm 处监测抵消效果
4. YDM6MIC 6 麦阵列天然适配：1 个伸出去做参考，其余做误差

**理论依据**：
- 窗户是噪声进入室内的"声学截面"，低频（<500Hz）可视作点源
- 参考麦在窗外的直达声和穿过窗户的噪声高度相关
- 因果裕度充足（噪声从窗外传到窗内有延迟）

**预期收益**：NR 从当前 2-3dB 提升到 10-15dB（低频），接近离线测试水平。

#### P1: 子带处理

**问题**：全频带统一收敛速度受限于最慢的频段。

当前全频带 FxNLMS 使用单一全局步长 μ=0.0001 驱动整个 0-8kHz 频带的自适应。
实际噪声信号通常是有色的（低频能量高、高频能量低），导致输入自相关矩阵的**特征值散布比**
（最大/最小特征值之比）很大。LMS 类算法的收敛时间与特征值散布比成正比——散布越大，
低能量频段收敛越慢。步长必须迁就最高能量频率（防止振荡），结果是最低能量频率几乎不收敛。

**方案**：
1. 使用分析滤波器组将信号分解为多个子带（如 8 个均匀子带，每个 ~1kHz 宽）
2. 每个子带独立运行 FxNLMS，各子带内频谱近似平坦 → 特征值散布比接近 1
3. 每个子带可独立选择最优步长（低频用大 μ，高频用小 μ）
4. 合成滤波器组重构全频带反噪声

**预期收益**：收敛速度提升 2-5 倍，各频段独立优化，对突发性非平稳噪声响应更快。

**代价与风险**：
- 分析/合成滤波器组引入额外群延迟（通常 2-5ms），会缩小 ANC 因果裕度
- 实现复杂度显著增加（滤波器组设计、子带间相位对齐）
- 当前系统的瓶颈在模拟前端（麦克风灵敏度、反馈路径），收敛速度尚非首要限制

#### P1: 啸叫检测 ✅ 已完成

**实现**：`include/howling_detect.h` + `src/howling_detect.c`

1. **DFT 频谱分析**：每 256 样本 (16ms) 对误差信号做 DFT（覆盖 62.5-1500Hz ANC 频段），
   汉宁窗减少频谱泄漏
2. **峰值检测**：峰均值比 >12dB 标记为候选啸叫频率
3. **状态机**：4 帧确认 (64ms) 后激活陷波器，8 帧无峰后自动释放
4. **IIR 陷波**：biquad 二阶陷波器 (r=0.96)，最多 2 路同时工作，直接作用于 anti_out
5. **全静态配置**：`#define HW_THRESH_DB/HW_PERSIST/HW_NOTCH_R` 等，原型落地零改动

**实测效果**：在正常降噪中不误触发（仅窄带自激才会激活），峰均值 <12dB 时安静运行。
与 safety_mute 互补——safety_mute 检测宽带反馈，啸叫检测锁定窄带自激频率。

#### P1: Wc 发散检测与自动回退

**问题**：当前仅靠 `err_rms > ref_rms` 触发安全静音，属于被动式、事后补救。实测中 Wc
系数可能在 MUTE 触发前已经暴涨（如之前 10x 增益测试中 anti 从 0.007 暴涨到 11.0），
导致输出饱和、非线性失真、滤波器发散。商业 ANC 的 DSP 固件中，发散检测是独立于 ANC
主循环的安全监控模块。

**检测指标**：
1. **Wc 系数幅度**：`max(|Wc[k]|) > Wc_max_threshold` → 系数暴涨，立即冻结
2. **Wc 变化率**：`||Wc_new - Wc_old|| / ||Wc_old|| > rate_threshold` → 异常快速变化
3. **误差功率趋势**：连续 N 秒 `err_rms` 不降反升 → 发散预警

**回退策略**：
1. 检测到发散 → 冻结 LMS 更新（`fxnlms_forward_only` 模式）
2. CrossFader 平滑回退到当前场景的 CNN 预设 Wc
3. 重新开始自适应，但步长减半（退避策略）
4. 若连续 3 次发散 → 固定使用 CNN 预设 Wc，停止自适应直到场景切换

**实现要点**：
- Wc 幅度阈值：经验值 ~5× stub_rms（超过这个值说明系数异常）
- 监控周期：每秒检查一次（与 CNN 同步）
- 与啸叫检测独立并行运行，互为补充

**预期收益**：消除突发发散导致的巨响，系统自愈能力达到商业产品水平。

#### P2: 输入过载保护

**现状**：已通过 `tanh()` 软限幅实现基础保护（`main_realtime.c:127-129`），防止吹气、关门等
大声压导致 FIR 滤波器饱和。这是商业 ANC 的标配——ADC 饱和或接近饱和时，线性模型失效，
LMS 梯度方向随机化，必须在进入自适应之前截断。

**进一步完善方向**：
1. 可配置限幅阈值（当前硬编码 `MIC_CLIP_MAX=1.0`）
2. 限幅计数器：统计限幅触发频率，超过阈值时降低 MIC_PRE_GAIN
3. 过载标志位：传给 CNN 场景分类器，辅助判断是否为"冲击噪声"场景

**预期收益**：已基本满足，后续主要是可配置性和监控完善。

#### P2: 冷启动静音

**问题**：系统启动或 RESET 后，Wc 从零开始收敛，前 1-3 秒 `err > dist`（NR 为负），
意味着扬声器在输出"错误的反噪声"——不仅没降噪，反而增加了噪声。实测中冷启动
NR 可达 -10 到 -20 dB，用户感知为"开机嘭的一声"。

**方案**：
1. 检测收敛状态：连续 0.5 秒 `err_rms < dist_rms × 0.5` 视为已收敛
2. 收敛前：反噪声输出乘以一个从 0 渐增到 1 的增益系数（如 200ms 线性斜坡）
3. 或者更简单：收敛前直接静音反噪声输出（`anti_out = 0`），仅保持 LMS 更新

**与现有软启动的区别**：
- 当前软启动：场景切换时 CrossFader 混合新旧 Wc（16 sample ≈ 1ms），针对的是 Wc 切换
- 冷启动静音：Wc 从零开始时抑制输出（1-3 秒），针对的是 Wc 初始收敛

**预期收益**：消除冷启动/RESET 瞬间的冲击噪声，提升用户体验。

### 方案 B：正式原型（共时钟，¥800-1500）

```
[4×驻极体麦]──┬── [UMC404HD 或 Scarlett 4i4] ──USB── [Windows PC/笔记本]

状态: git revert 162d357 恢复 F-A/F-B, 预计 NR 10-18dB
```

### 独立运行（脱离电脑）

上述方案均需 PC 提供算力。若要脱离电脑独立运行：

| 路径 | 硬件 | 工作量 | 适用 |
|------|------|--------|------|
| **Windows 迷你主机** | Intel NUC / LattePanda (~¥1500) | **零**（代码直接跑） | 展会原型、小批量 |
| **ARM Linux 板** | 树莓派 5 + 音频 HAT (~¥800) | 中等（PortAudio DLL→ALSA, Windows→POSIX） | 便携原型 |
| **DSP 芯片** | ADI SHARC / Qualcomm ANC SoC | 巨大（全代码重写定点数, CNN不可行） | 量产 |

**推荐路径**：原型阶段用 Windows 迷你主机（零移植成本），量产阶段移植到 ARM Linux 或定制 DSP。
