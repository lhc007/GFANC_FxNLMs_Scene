## 一、已知问题与根因

### 1.1 扬声器输出音量不足

**现象**：播放马路噪声（~70 dB SPL）时，扬声器反噪声几乎听不到。

**根因**：YDM6MIC 麦克风灵敏度为 **-26 dBFS @ 94 dB SPL**。这意味着：

| 声压级 (SPL) | 场景 | 数字输出 (float32) |
|-------------|------|-------------------|
| 120 dB | 声学过载点 | 1.0 (满幅) |
| 94 dB | 摩托车近距 | 0.05 |
| 70 dB | 马路噪声 | 0.003 |
| 40 dB | 安静房间 | 0.0001 |

**代码实际状态**：

已实现可调输入预增益 `MIC_PRE_GAIN=10x`（`main_realtime.c:29`），ref 和 err 通道均已应用。
反馈抵消（P0）完成后，10x 增益可稳定运行，无啸叫。
Wc 构造使用自动 RMS 归一化（`scene_controller.c:99`）。

**FxNLMS 的自动补偿**：

功率归一化 LMS 对小信号有内在补偿：`ΔWc = -μ × err × xd / power`。低输入时 power 小，有效步长自动放大。
MIC_PRE_GAIN 同时放大参考和误差信号，稳态 anti_out 由误差麦处的实际声学噪声决定，不随增益线性变化。

**真正的瓶颈**：
1. **麦克风灵敏度**（-26 dBFS @ 94dB SPL）：YDM6MIC 是主要限制。即使噪声源覆盖全部麦克风，
   数字信号仍微弱（ch0≈0.001），需要硬件前置放大器将信号抬升 20-40dB
2. **声学解相关**（见 1.3 节）：噪声源必须同时覆盖参考麦和误差麦，否则 ANC 不触发或效果差
3. 扬声器最大 SPL：DAC 满幅 ±1.0 是硬天花板
3. 麦克风自噪声：系统残差底噪约 0.0003 (~50 dB SPL)，数字增益无法改善

**解决方向**：
1. **反馈抵消（P0）**——优先级最高的软件项，做成后可安全提升增益到 20-50x
2. **硬件前置放大器**——20-40 dB 模拟增益，改善 SNR
3. **扬声器功放**——增大驱动功率
4. **更换麦克风**——高灵敏度 ANC 麦克风

### 1.2 声反馈（啸叫）

**现象**：增益过大时扬声器输出被参考麦拾取，形成正反馈环路。

**根因**：前馈 ANC 的固有缺陷——参考麦和扬声器之间缺乏物理隔离。

**当前缓解措施**：
- 输出限幅 ±1.0
- 反馈检测（全通道 RMS 相近时自动降增益）
- 安全静音（err > ref 时 MUTE）

**解决方向**：
1. **反馈路径建模与抵消**——测量扬声器→参考麦传递函数，从参考信号中减去
2. **物理隔离**——参考麦朝外、扬声器朝内，中间加物理屏障（耳机 ANC 标准做法）
3. **自适应反馈抵消**——额外自适应滤波器实时估计并消除反馈分量

### 1.3 开放空间声学解相关

**现象**：离线测试 NR=15dB，但实时开放空间中 NR 仅 2-3dB（外部噪声下）。

**根因**：离线测试中参考信号和误差信号经过同一初级路径，相关度 100%。
真实房间中，噪声经墙壁反射、混响后到达误差麦，与参考麦采集的直达声**部分不相关**。
LMS 无法抵消不相关的噪声分量。这是前馈 ANC 在开放空间的物理极限，非算法缺陷。

**验证**：离线 `main.exe` 仍保持 15dB → 算法未退化，瓶颈在声学环境。

**解决方案**：
1. **窗户 ANC 配置（推荐实验）**——参考麦伸窗外，扬声器+误差麦在窗内侧。
   噪声从窗户进入的路径确定，解相关程度远低于全室内反射 → 预期 NR 10-15dB
2. **多通道参考**——利用 YDM6MIC 的 6 个麦克风做波束成形，提取直达声分量
3. **反馈 ANC 辅助回路**——用误差麦自身信号做反馈控制，不依赖参考麦相关性

## 代码审查修复记录 (2026-07-22)

### 已修复项

#### ✅ FIX-1: MinMax Scaler 静默输入保护不足

**问题**：[src/scene_controller.c:45-50](src/scene_controller.c#L45-L50) MinMax scaler 的静默保护阈值 `1e-10f`
过低。当音频接近静音时 `denom = 2e-10`，CNN 输入被放大 ~5×10⁹ 倍，经 Conv1D 累加 (STEM_K=80)
后 float32 溢出到 ±Inf，经 softmax 产生 NaN，Wc 用垃圾数据构建 → 输出错误。

**影响**：静默/极低音量场景下，CNN 输出 NaN → argmax 随机场景 → Wc 随机 → 抗噪声可能反相，
触发正反馈啸叫。

**修复**：
- 阈值从 `1e-10f` 提高到 `1e-6f`（对应约 -120 dBFS，远低于任何有效信号）
- 低于阈值时 `memset(cnn_in, 0, ...)` 全零填充而非 `memcpy` 原始音频
- 位置：[src/scene_controller.c](src/scene_controller.c) 第 47-50 行

#### ✅ FIX-2: CNN 前向失败返回值未检查

**问题**：[src/scene_controller.c:53-54](src/scene_controller.c#L53-L54) `cnn_m5_forward()` 的返回值被忽略。
当 CNN 内部 `malloc` 失败时返回 -1，但 `logits` 是栈上的未初始化垃圾数据，后续 softmax/argmax/Wc 构造
全部基于垃圾值。

**影响**：内存不足时 Wc 被设置为随机值，输出不可预测。

**修复**：
- 检查 `cnn_m5_forward()` 返回值
- 失败时保持上一帧场景（`sc->cur_scene`）和对应的 Wc
- 首帧失败时回退到 scene 0
- 位置：[src/scene_controller.c](src/scene_controller.c) 第 53-69 行

#### ✅ FIX-3: NaN/Inf 无声传播至音频输出

**问题**：整个代码库无 `isnan()`/`isinf()` 检查。任何环节产生 NaN（除零、log10 负数、
MinMax 溢出等）会无声传播至 `anti_spk`。更严重的是，输出钳位 `if (anti_spk[s] > 1.0f)` 
对 NaN 无效（NaN 比较永远返回 false），NaN 直接进入 DAC → 扬声器。

**影响**：NaN 值进入音频 DAC 可能导致硬件损坏或听力损伤（取决于 DAC 的异常值处理）。

**修复**：
- 在 `anti_spk` 钳位前加 `isfinite()` 检查，非有限值清零
- 在 48kHz 输出内插循环中也加 `isfinite()` 检查
- 位置：[main_realtime.c](main_realtime.c) 第 202-206 行、第 265-267 行；[main.c](main.c) 第 359-362 行

#### ✅ FIX-4: FxNLMS Leak 与 step_size 耦合导致实际无效

**问题**：[src/fxnlms_mimo.c:93-94](src/fxnlms_mimo.c#L93-L94) leak 公式为 `wc *= (1.0f - step_size * leak)`。
当前参数 `step_size=0.0001, leak=1e-5` → 有效衰减 `1 - 1e-9`。在 float32 精度下 `1.0f - 1e-9f = 1.0f`
（完全无效果），Wc 无任何正则化。

**影响**：长期运行中 Wc 可能漂移/饱和，无内在机制限制系数增长。之前需依赖 `safety_mute`
被动检测发散。

**修复**：
- 公式改为 `wc *= (1.0f - leak)`，leak 与 step_size 解耦
- leak 参数从 `1e-5f` 调整为 `1e-6f`（~1.5%/秒衰减，float32 可分辨）
- 位置：[src/fxnlms_mimo.c](src/fxnlms_mimo.c) 第 93-94 行；[main.c](main.c) 第 192 行；[main_realtime.c](main_realtime.c) 第 393 行

#### ✅ FIX-5: 啸叫陷波器 IIR 状态跨扬声器串用 (原 B-2)

**问题**：[src/howling_detect.c:247-253](src/howling_detect.c#L247-L253) 两个扬声器共用同一组 IIR 状态变量
`x1[i], x2[i], y1[i], y2[i]`。扬声器 0 处理后状态被更新，扬声器 1 接着用被污染的
历史状态继续滤波 → 第二个扬声器的陷波相位/幅度错误。

**影响**：多扬声器场景下陷波效果不可靠，可能导致某扬声器陷波深度不足或过度衰减。

**修复**：
- IIR 状态数组从 `[HW_MAX_NOTCHES]` 扩展为 `[HW_S][HW_MAX_NOTCHES]`（HW_S=2）
- `add_notch()` 初始化所有扬声器的状态
- `remove_notch()` 搬运所有扬声器的状态
- `howling_tick()` 两处 `notch_apply` 调用传入 `[s][i]` 索引
- 位置：[include/howling_detect.h](include/howling_detect.h) 第 26、45-46 行；
  [src/howling_detect.c](src/howling_detect.c) 第 148-151、167-173、193-196、249-253 行

#### ✅ FIX-6: Wc RMS 退化无告警

**问题**：[src/scene_controller.c:99](src/scene_controller.c#L99) 当 Wc 全零时（blend 权重全部接近零
或 centroid 训练异常），RMS 对齐使用 `scale=1.0`，Wc 保持全零 → ANC 静默，但无任何日志输出，
调试时难以发现。

**影响**：ANC 静默时无法区分是 Wc 退化还是 acoustic path 解相关。

**修复**：
- 在 RMS 对齐前检查 `wc_rms < 1e-6`，低于阈值时 stderr 告警（限 3 次）
- 位置：[src/scene_controller.c](src/scene_controller.c) 第 113-122 行

### 详解

#### P0: 反馈抵消 ✅ 已完成

**实现**：`src/calibrate_feedback.c` + `main_realtime.c`

1. **校准程序** (`calibrate_feedback.exe`)：扬声器播放 4 秒白噪声，参考麦录制，
   NLMS 辨识 256 tap FIR → 存入 `data/feedback_path.bin`
2. **运行时**：每样本 `ref_corrected = ref_raw - Fb_path ⊗ anti_output`，
   反馈 FIR 的输出抵消扬声器漏回参考麦的分量
3. **自动降级**：若 `feedback_path.bin` 不存在，自动禁用，不影响正常 ANC

**实测效果**：
- 反馈路径：peak @ tap 7 (0.44ms ≈ 15cm)，衰减约 -34dB
- 10x 增益稳定运行（之前无抵消时 6x 即振荡）
- 15x 增益在噪声源良好耦合时 anti 削波（>0.5 RMS），证明 ANC 算法有效但需适度增益
- 反馈抵消量 RMS ~0.0001-0.0015（取决于 anti 幅度）
- 当前核心瓶颈：麦克风灵敏度 + 声学解相关 (见 1.3 节)

#### P1: 增益标定 → 已评估, 不实施

**评估结论 (2026-07-22)**：当前单硬件 + 反馈抵消已确定 MIC_PRE_GAIN=10x 为安全值。FxNLMS 功率归一化自动补偿信号电平变化。真正上限是反馈路径残余而非麦克风灵敏度，标定测不出反馈边界。换硬件时手动改一行 `#define` 即可。自动标定引入环境噪声污染/扬声器依赖/启动延迟等新故障点，收益不抵风险。

#### P1: 窗户 ANC 实验配置

**背景**：实测发现开放空间中参考麦和误差麦的声学解相关是 NR 的主要瓶颈（NR 仅 2-3dB
vs 离线 15dB）。噪声经墙壁反射/混响到达误差麦的分量与参考麦采集的直达声不相关，
LMS 无法抵消。将参考麦置于噪声源侧（室外）、扬声器和误差麦置于受保护侧（室内窗户
平面），可最大化参考-误差相关性。

**实验方案**：
1. 参考麦伸出窗外，朝外采集马路噪声直达声
2. 扬声器对准窗户中心，朝室内发射反噪声
3. 误差麦在窗户内侧 10-20cm 处监测抵消效果
4. YDM6MIC 6 麦阵列天然适配：1 个伸出去做参考，其余做误差

**理论依据**：
- 窗户是噪声进入室内的"声学截面"，低频（<500Hz）可视作点源
- 参考麦在窗外的直达声和穿过窗户的噪声高度相关
- 因果裕度充足（噪声从窗外传到窗内有延迟）

**预期收益**：NR 从当前 2-3dB 提升到 10-15dB（低频），接近离线测试水平。

#### P1: 子带处理 → 已评估, 不实施

**评估结论 (2026-07-22)**：子带理论优势（降低特征值散布→加速收敛）在本系统中被 CNN 场景预设抵消——Wc 从 CNN Blend 构造而非零初始化，起点已接近最优。场景记忆恢复已收敛 Wc 后切换无需重新收敛。2-5ms 额外群延迟吃掉 50cm 系统本就不宽裕的因果裕度。实现复杂度（滤波器组设计/相位对齐/多 LMS 实例）远超收益。当前系统瓶颈在声学解相关(§1.3)，非收敛速度。

#### P1: 啸叫检测 ✅ 已完成

**实现**：`include/howling_detect.h` + `src/howling_detect.c`

1. **DFT 频谱分析**：每 256 样本 (16ms) 对误差信号做 DFT（覆盖 62.5-1500Hz ANC 频段），
   汉宁窗减少频谱泄漏
2. **峰值检测**：峰均值比 >12dB 标记为候选啸叫频率
3. **状态机**：4 帧确认 (64ms) 后激活陷波器，8 帧无峰后自动释放
4. **IIR 陷波**：biquad 二阶陷波器 (r=0.96)，最多 2 路同时工作，直接作用于 anti_out
5. **全静态配置**：`#define HW_THRESH_DB/HW_PERSIST/HW_NOTCH_R` 等，原型落地零改动

**实测效果**：在正常降噪中不误触发（仅窄带自激才会激活），峰均值 <12dB 时安静运行。
与 safety_mute 互补——safety_mute 检测宽带反馈，啸叫检测锁定窄带自激频率。

#### P1: Wc 发散检测与自动回退 ✅ 已实现 (2026-07-22)

**已实现**：每秒检查 `max|Wc| > 5×stub_rms` → 设置 `freeze_lms` 跳过梯度更新。INIT/场景切换自动清除冻结。位于 `fxnlms_mimo.c`/freeze_lms 字段 + `main_realtime.c` 主循环。

**待完善**（后续可加, 当前非必需）：
- Wc 变化率检测：`||Wc_new - Wc_old|| / ||Wc_old||` 异常快速变化
- 自动回退：冻结后 CrossFader 回退到 CNN 预设（当前仅冻结, 需手动场景切换触发重置）
- 退避策略：恢复后步长减半

#### P2: 输入过载保护

**现状**：已通过 `tanh()` 软限幅实现基础保护（`main_realtime.c:127-129`），防止吹气、关门等
大声压导致 FIR 滤波器饱和。这是商业 ANC 的标配——ADC 饱和或接近饱和时，线性模型失效，
LMS 梯度方向随机化，必须在进入自适应之前截断。

**进一步完善方向**：
1. 可配置限幅阈值（当前硬编码 `MIC_CLIP_MAX=1.0`）
2. 限幅计数器：统计限幅触发频率，超过阈值时降低 MIC_PRE_GAIN
3. 过载标志位：传给 CNN 场景分类器，辅助判断是否为"冲击噪声"场景

**预期收益**：已基本满足，后续主要是可配置性和监控完善。

#### P2: 冷启动静音

**问题**：系统启动或 RESET 后，Wc 从零开始收敛，前 1-3 秒 `err > dist`（NR 为负），
意味着扬声器在输出"错误的反噪声"——不仅没降噪，反而增加了噪声。实测中冷启动
NR 可达 -10 到 -20 dB，用户感知为"开机嘭的一声"。

**方案**：
1. 检测收敛状态：连续 0.5 秒 `err_rms < dist_rms × 0.5` 视为已收敛
2. 收敛前：反噪声输出乘以一个从 0 渐增到 1 的增益系数（如 200ms 线性斜坡）
3. 或者更简单：收敛前直接静音反噪声输出（`anti_out = 0`），仅保持 LMS 更新

**与现有软启动的区别**：
- 当前软启动：场景切换时 CrossFader 混合新旧 Wc（16 sample ≈ 1ms），针对的是 Wc 切换
- 冷启动静音：Wc 从零开始时抑制输出（1-3 秒），针对的是 Wc 初始收敛

**预期收益**：消除冷启动/RESET 瞬间的冲击噪声，提升用户体验。
