# 窗户 ANC 可行性 — 因果限制、实测与实现方案

> **整合自**: `因果性限制与窗户ANC可行性_参考.md`(2026-08-03 理论) + `2026-08-04_实时ANC实测与窗口降噪规划.md`(实测) + 2026-08-05 DSP 可行性分析
> **背景**: 目标是对 **125×45cm** 窗户开口实现 **100-800Hz 中频胎噪**主动隔声(整窗声压 →0 为理想极限,可达 ~6-9dB 能量平均)。
> **核心问题**: 前馈 ANC 的因果性(预览时间)决定宽带降噪上限;当前 PC 原型被 12.5ms 声卡延迟锁死。

---

# 第一部分:因果性限制(理论)

## 1. 预览时间(causality / preview time)

前馈 ANC 能否抵消宽带随机噪声,由**预览时间**决定:

```
预览时间 = 参考麦→误差麦声学延迟 − (处理链延迟 + 扬声器→误差麦声学延迟)
```

- **预览时间 > 0** → 参考麦提前听到噪声,控制器有"提前量" → 宽带可实时对消(频率上限受预览大小限制)。
- **预览时间 < 0** → 反噪声比噪声晚到误差麦 → 随机宽带不可对消(只能消窄带/周期 + 部分低频)。

**当前 PC 系统实测值**:

| 分量 | 值 |
|------|-----|
| 参考→误差声学延迟(64cm / 343) | +1.9ms |
| ANC 带通群延迟(64tap, 2026-08-04 砍短前 256tap=−8ms) | −2ms |
| 声卡环路延迟(UMC ASIO, 128 样本缓冲,实测) | −8.4ms |
| 扬声器→误差声学延迟 | −0.4ms |
| **净预览** | **≈ −9ms**(砍带通前 −18.5ms) |

> 因果缺口为负 → 对随机宽带(相关时间 < 缺口,即 >~55Hz 宽带)不可实时对消;<55Hz 宽带 + 窄带/周期成分可消。**这就是实时 NR 只到 4-6dB 的根本原因。**

## 2. 两种"延迟"不能混淆

| 延迟 | 值 | 有没有问题 |
|------|-----|-----------|
| **CNN→Wc 交接**(慢环路,1Hz) | 1 秒 | ✅ **无问题**——CNN 是"暖启动"(提供 Wc 起点),FxLMS 每样本持续追当前噪声 |
| **前馈处理链**(快环路,每样本) | ~12.5ms | ❌ **这才是问题**——反噪声到达时间被物理链路锁死,与 Wc 无关 |

**关键认知**: Wc(控制滤波器)只决定反噪声的**形状**(频率/相位),**不决定到达时间**。无论 Wc 多准、CNN 多快,反噪声都要走处理链。场景降噪帮的是"可预测"噪声(窄带/周期/缓慢变化),对随机宽带无用。

# 第二部分:窗户 ANC 论文对照(Lam et al. 2020)

论文在 1m×1m 全尺寸家用窗上实现 **7.51-10.14 dB**(能量平均 SPL)真实宽带城市噪声降噪。它做到的 10dB 与当前系统条件**根本不同**:

| 条件 | 论文 | 当前 PC 原型 |
|------|------|---------|
| 扬声器数 | **24 个** 4.5cm 小扬声器铺满窗洞 | 2 个 |
| 误差麦 | 运行时**不装**(离线 FxLMS 训练固定 FIR) | 3 个,持续自适应 |
| 参考麦 | 单个,**窗户外侧**(朝噪声源) | 1 个,距误差麦 64cm |
| 控制器 | 实时 **DSP,~ms 级低延迟** | PC + UMC,12.5ms 环路 |
| 控制频段 | **300Hz-1kHz 有效,500Hz 以上最强,<300Hz 几乎无效**(小扬声器低频效率差) | <300Hz + 全频段窄带 |

**为什么论文能、当前不能**:

```
论文: 预览(窗外 3-6ms) − (DSP ~2ms + 扬声器 ~0.5ms) = 余量正 → 300Hz-1kHz 可控
当前: 预览(1.9ms) − (12.5ms + 0.4ms) = 负 → 中高频宽带不可控
```

**决定性差异 = 那 12.5ms 声卡延迟。** 论文用低延迟 DSP,PC 声卡把因果性吃光了。参考麦 64cm(1.9ms 预览)并不算短,被声卡延迟拖垮 —— **关键在延迟,不在参考麦距离。**

> 论文 10dB 是**中频段(300Hz-1kHz)**,500Hz 以上最强,<300Hz 几乎没控制(小扬声器限制) —— 与早期"控低频"正好**互补**,不是全频段 10dB。论文用 24 通道做**空间声场控制**(让窗洞成为声压释放边界),这是 2 扬声器做不到的。
> **对我们的启示**: 论文证明**中频(300-1000Hz)用小喇叭阵列可行(~10dB)**——而这正是现代车外噪主体(胎噪)的频段,详见 §4.6。

# 第三部分:实时实测与硬件调试(2026-08-04/05)

## 3.1 灵敏度根因:模拟增益旋钮,不是软件

- "不贴麦不收音"根因 = UMC 输入旋钮太低。旋钮拧到最大后 ref 自然到 -30dBFS,自动增益回 1x。
- 旧参数(wc_target=0.03 / step=3e-7 / MIC_GAIN=20 / DIVERGE_ANTI=5)是弱信号期诊断兜底,**在信号健康时全部失效**,已废弃。
- 注意机制:发散救援阈值 = `diverge_anti_rms / mic_pre_gain`,mic_pre_gain=20 时阈值被压到 0.0125 → NR 卡死。

## 3.2 校准质量规则

- 校准时 **SIG 常亮、CLIP 不亮**。CLIP = ADC 削波(数据进程序前,不可逆),污染路径辨识。
- 探针响度 `GFANC_CAL_NOISE`(默认 0.9,反馈+次级都支持),旋钮最大时用 0.4-0.5。
- **校准和运行必须同一旋钮位置**(路径系数嵌入模拟增益)。
- ERLE<8dB 弱路径自动置零(保护),失败路径每次校准会漂移(e0,s0 / e1,s1)。

## 3.3 125Hz 反馈振荡

**机理**: 扬声器反噪音→误差麦听到→FxLMS 当"要消的噪音"继续消→正反馈环。12.5ms 纯延迟反馈环天然在 `1/(2τ)≈40Hz` 及奇次谐波(120/200Hz)起振 —— **125Hz 是延迟自激,与外部声源无关**。

**铁证**: 陷波 ON(默认阈值 12)→ 稳定;陷波 OFF(HW_THRESH=15)→ 周期性"收敛→err=0.7 爆炸→静音"。

**处理**: ①误差麦旋钮降到 SIG 能亮(别降过);②扬声器与误差麦拉开/错向;③陷波保持默认兜底。

## 3.4 环路延迟构成与砍法

```
环路 12.5ms = ASIO 管线 8.4ms(128 样本@48k=2.67ms 只是部分)+ Ŝ 声学 4ms(物理)
```

| 杠杆 | 省 | 状态 |
|---|---|---|
| 带通 256→64tap | ~6ms(8→2ms) | ✅ 已改 |
| GFANC_BUFFER 128→64 | ~1.5-2ms | ⚠️ 需带 GFANC_BUFFER=64 重校准,否则延迟模型失配 |
| 参考麦往窗外移 | 预览 1.9→3ms+ | 物理,免费 |

## 3.5 算法优化(2026-08-05,commit 04b6444)

| 改动 | 效果 |
|---|---|
| **VS-LMS(双 EMA 尖峰检测)** | 误差相对基线跳变→降步防反馈过冲,平滑收敛全速。实时 step 3e-7/5e-7 从"7次MUTE振荡"变稳定 |
| **leak 默认 5e-6→5e-7** | 弱信号下 Wc 能长起来(离线 1.4→13dB 的收敛杠杆) |
| **虚拟延迟/预览**(`GFANC_VIRT_DELAY_MS`/`GFANC_VIRT_PREVIEW_MS`) | 离线验证因果性:延迟→Ŝ,预览→Pri |

**验证结果(离线,马路噪音):**

| 配置 | NR_true |
|---|---|
| 无延迟(算法上限) | 13.1dB |
| **预览 3ms + 延迟 ≤2ms(窗口场景)** | **~15dB** ✅ |
| 预览 3ms + 延迟 5ms | 7.1dB |
| PC 现状(延迟 12.5ms) | ~6dB(印证实时) |

> ⚠️ **口径说明(2026-08-07)**: 上表为**离线 NR_true**——干净模型、无硬件环路、误差麦单点/算法上限。**实时整窗"能量平均" NR 远低于此**(空间欠采样+相干性): 2S≈2-4dB、6S≈5-9dB(详见 §5.2 双口径)。"整窗声压→0"是**理想极限,非可达指标**(Lam 2020 用 24 单元也仅 ~10dB)。

**实时**: 默认 NR 4.4→**6.2dB**,高步长稳定。**NR_est 不可信**(依赖 Ŝ + 误差麦灵敏度,误差麦降太狠读数落地板),唯一真值 = 离线 NR_true,实时以人耳为准。

# 第四部分:DSP 可行性分析(2026-08-05 新增)

## 4.1 2ms 环路延迟预算

| 组成 | 通用音频 codec | **ANC 级低延迟 codec** |
|---|---|---|
| ADC 转换 | 0.5-1ms | 0.2-0.5ms |
| DSP 处理(逐样本中断) | ~0.1ms | ~0.1ms |
| DAC 转换 | 0.5-1ms | 0.2-0.5ms |
| 环路滤波(最小相位) | 0.2-0.5ms | 0.2-0.5ms |
| **合计** | **1.3-2.6ms ⚠️ 紧/超** | **0.7-1.6ms ✅** |

**结论:2ms 可实现,但必须 ANC 级低延迟 codec**(ADAU1787 或高速 I2S 转换器)。通用 codec 的 1-2ms 转换延迟直接吃光预算。

## 4.2 通道数算力(MIMO FxLMS,L=256)

| S=6, E=6(S=E 满定) | 36 | ~0.5 GMAC/s | 1.4 GMAC/s |
| S=6, E=3(过定) | 18 | ~0.25 GMAC/s | 0.74 GMAC/s |
| S=12, E=12(800Hz 整窗) | 144 | ~1.2 GMAC/s | 3.5 GMAC/s |

## 4.3 扬声器数量与空间上限(125×45cm 窗,2026-08-07 更新)

按 λ/2 空间采样,整窗 p→0 需要的控制单元(125cm 宽为主约束):

| 频段 | 单元数(125×45 窗) |
|---|---|
| 20-300Hz | 2-3 |
| 20-400Hz | 3 |
| 20-500Hz | 6-8 |
| 20-800Hz | **12-18**(125/21≈6 列 × 45/21≈2-3 行) |

**中频胎噪目标(100-800Hz,§4.6)**: **12 扬声器(2×6,21cm 间距)** 即可覆盖——8 误差麦(非 12)省算力(§4.2)。
早期 6 扬声器(2×3)只到 ~450-500Hz,不够中频胎噪目标。

## 4.4 参考麦相干性约束(预览 vs 预测的权衡)

参考麦要预测误差麦处的扰动,靠**相干性**。距离越远:
- 预览↑(因果裕量)✅
- 相干性↓(高频预测变差)❌

**频率相关的**: 场在距离 d 内失相关,相干良好上限 ≈ c/d。

| 参考→误差 | 预览 | 相干良好上限 | 800Hz 预测 |
|---|---|---|---|
| 50cm | 1.46ms | ~686Hz | 勉强 |
| **1m** | 2.9ms | **~343Hz** | **失相关,消不动** |
| 2m | 5.8ms | ~170Hz | ✗ |

**关键结论: 单参考麦放 1m,在 800Hz 基本失相关** —— 参考麦听到的 800Hz 成分和窗面实际传入的不是一回事。要 800Hz 必须**参考阵列**(多支参考麦采样入射场空间结构,间距 ~21cm)。

**完整 800Hz 配置(所有约束):**

| 部件 | 配置 | 依据 |
|---|---|---|
| 控制阵列 | **12 扬声器 + 8 误差麦**(2×6,≤21cm,§5.2 务实) | 空间采样 @800Hz(误差麦<扬声器省算力,§4.2) |
| 参考阵列 | **~6-12 支参考麦**,窗外 1m,间距 ~21cm | 补 800Hz 相干性 |
| DSP | ≤2ms(ANC 级 codec) | 因果 |
| 扬声器→误差麦 | ≤31cm(Ŝ ≤0.9ms) | `DSP 2ms + Ŝ ≤ 预览 2.9ms` |

**因果核算**: 预览(窗外1m→窗面)=2.9ms;控制路径 = 2ms DSP + 0.6ms(20cm格内)= 2.6ms < 2.9ms ✅

## 4.5 当前代码延迟/算力优化清单(2026-08-07,Phase-2 设计依据)

> 以下为当前 PC 原型 (`main_realtime.c`/`fxnlms_mimo.c`) 移植到嵌入式时的优化空间。
> **核心认知: 通道数影响算力需求,不影响延迟**——逐样本架构下延迟 = 采样周期 + codec 转换,
> 与通道数无关(只要 DSP 在 62.5µs 内算得完)。

### 4.5.1 延迟优化空间

| 杠杆 | 省多少 | 代价 |
|---|---|---|
| **块缓冲→逐样本架构** | **~2.7ms**(消掉 GFANC_BUFFER=128) | 架构重设计,嵌入式必须(PC 的 ASIO 只能块缓冲) |
| `GFANC_BUFFER` 128→64 (PC 过渡) | ~1.3ms | 爆音风险 + 需重校准延迟模型 |
| ANC 带通 64→32tap | ~1ms | 滤波质量下降(20/1500Hz 过渡带宽) |
| 控制率 16k→32k | 每样本 62.5→31µs | 算力 ×2 + L ×2,不值 |

**关键**: PC 的 8.4ms ASIO 是驱动/声卡级硬瓶颈,代码改不动;嵌入式逐样本架构直接消掉 2.7ms 块缓冲,
是最大的延迟解放。**2ms 延迟的 3 个硬条件**: ① ANC 级低延迟 codec(ADAU1787/高速 I2S,通用 codec
1-2ms 转换直接吃光预算); ② 逐样本处理(非块缓冲); ③ DSP 峰值吞吐 > 需求。

### 4.5.2 算力优化空间

当前 ~0.2-0.3 GMAC/s(2S+3E+1024L),FxLMS 占大头。已优化的: R-11(anti_est 采样)、R-12(环形缓冲)、
R-24(CNN 静态缓冲)。

| 杠杆 | 省多少 | 代价/注意 |
|---|---|---|
| **L: 1024→512** | **FxLMS 算力减半(~50%)** | 频域分辨率 15.6→31Hz(20-1500Hz 仍够);**需重训导出 sub_filters.bin** |
| **SIMD/向量化** | 嵌入式 DSP 向量单元 | 当前双段循环零取模已 SIMD 友好,移植成本低 |
| 弱路径裁剪 | 少量 | e1-s1 等 ERLE 置零路径可跳过计算 |

### 4.5.3 结论

- **当前代码不是算力瓶颈**(~0.3 GMAC/s 很小);延迟瓶颈在**块缓冲架构 + ASIO**,嵌入式重设计时消掉。
- 扩到 6×6 通道(0.5 GMAC/s)时,**L 减半 + SIMD** 让 SHARC 1.5 GMAC/s 更从容(3× 裕量保持)。
- L 减半留到扩通道时一并做——否则现在减半白减且 golden 要重接受。

## 4.6 目标噪声频段分析(2026-08-07,居民视角)

### 4.6.1 居民楼听到的三类马路噪声

| 声源 | 主要频段 | 特征 |
|---|---|---|
| **车噪**(发动机/排气/车流) | 50-400Hz | 低频"轰隆"; **但现代车(尤其电车)发动机已很安静** |
| **胎噪**(轮胎-路面) | 500-2000Hz(全谱) | 中频;车速>40-60km/h 后是车流主成分 |
| **人声/市井嘈杂** | 300-3400Hz | 中高频,说话清晰度靠此段 |

**关键认知**: 现代汽车(尤其电车)发动机噪声被压制得很低 → **车外噪声主体 = 胎噪(中频)**,不是低频轰鸣。
人耳对 500Hz-4kHz 最敏感(A 计权),所以最"吵"的是中频胎噪 + 说话声。

### 4.6.2 夜晚远处单车的实际听感

城区夜晚安静街,30-50 迈(48-80km/h)车辆远处驶来:
- **是胎噪,不是风噪**——速度分界: 乘用车 30-50 迈时胎噪主导;风噪需 >110km/h(70 迈);发动机现代车几无声。
- **距离低通效应**: 远处传来时胎噪高频分量被大气吸收/地面效应衰减 → 听到的是**低通后的胎噪,主能量 ~100-800Hz**。

### 4.6.3 目标设定: 中频胎噪 100-800Hz

- **目标频段**: **100-800Hz**(实测听感),而非早期"低频轰鸣 50-400Hz"或"全谱到 2000Hz"。
- **相干性**: 定向车流(平面波式)在窗外 1m 参考下中频相干可行(Lam 2020 实测 300-1000Hz ~10dB);
  居民楼多径反射会降低相干性 → **必须实测验证**(阻塞项)。
- **扬声器**: 中频用小口径(4.5-8cm)即高效——**反面教训: Lam 用 4.5cm 小喇叭低频(<300Hz)几乎无效,但中频 300-1000Hz 做到了 ~10dB**。

## 4.7 麦克风选型标准(2026-08-07,ECM8000 教训)

**背景**: 项目此前用 ECM8000(-70dB 测量麦)当参考/误差麦,**实际应用不行**——低灵敏度需最大增益、噪声底高、
位置极敏感、不防水。**窗口 ANC 的麦克风是实用传感器,不是测量仪器**;选错会污染 Ŝ/环路/NR 全部测量。

| 要求 | 参考麦(窗外) | 误差麦(窗内) |
|---|---|---|
| **灵敏度** | **≥ -45dB**(越高越好,免极端增益) | ≥ -45dB |
| **频响** | **100-800Hz 平坦**(±3dB 内即可) | 同 |
| **防水/耐候** | **必须**(窗外日晒雨淋) | 不需要 |
| **噪声底** | 低(A 计权 ≤ ~30dB SPL) | 同 |
| **尺寸** | 小、易固定 | 小、易固定 |

**推荐类型**: 高灵敏度驻极体电容(MEMS/预极化)或专用户外麦克风;**避免测量级麦克风**(ECM8000 等,
-60~-70dB 低灵敏度为频响平坦牺牲了实用性)。100-800Hz 频段内普通驻极体/MEMS 足够平坦。

**为什么之前不行**: ECM8000 低灵敏度 → 需最大增益 → 放大噪声底 + 位置极敏感 + 不防水。
**麦克风选型错误 = 整个 ANC 的 SNR 和路径测量都不可靠**。

# 第五部分:窗户 ANC 方案与路线图

## 5.1 两条路线对比(2026-08-07 修订:目标=中频胎噪)

| | **务实路线(中频胎噪 ~800Hz)** | **研究级(到 1000-2000Hz)** |
|---|---|---|
| 控制单元 | **12 扬声器 + 8 误差麦**(2×6,21cm 间距) | 20-24 扬声器 + 误差麦(≤17cm) |
| 参考 | **1 支参考麦窗外 1m**(中频相干需实测) | **参考阵列** |
| DSP | **C6748/ARM 级(~2-3 GMAC/s,$10-50)** + ANC 级 codec | 更强 DSP |
| 覆盖 | **100-800Hz 中频胎噪**(现代车外噪主体) | 到 1000-2000Hz |
| 复杂度 | **可落地**(~12 单元) | 贵,密度翻倍 |
| 预期 | 整窗能量平均 ~6-9dB(点测 ~10-15dB) | 更宽频带 |

**判断(2026-08-07)**: 现代车(尤其电车)发动机已安静,车外噪声主体是**胎噪(中频)**;夜晚远处听感经距离低通后主能量 ~100-800Hz。
所以目标从"低频轰鸣"改为**中频胎噪 100-800Hz**——12 单元(2×6,21cm)即可覆盖,性价比合适。

> **双口径定义**: ① **整窗能量平均** = 开口面多点采样的声压能量平均降噪(目标指标,可达 6-9dB);② **误差麦点测** = 优化点处的单点降噪(易高估,10-15dB)。目标"整窗声压→0"为理想极限。

## 5.2 推荐方案(中频胎噪 100-800Hz)

| 项 | 选型 |
|---|---|
| **控制器** | **TI C6748($10-20,L=512) 或 ARM 模块($20-50,float 原生)** + ANC 级低延迟 codec;⚠️ ADAU1467 是 SigmaDSP 图形化**不能跑 C 代码**;开发板见 §4.2 |
| **延迟目标** | **≤2ms**(逐样本:算完所有通道在 62.5µs 内) |
| **通道** | **12 扬声器 + 8 误差麦**(2×6,21cm 间距,盖 125×45 窗 800Hz) |
| **扬声器** | 中小口径(4.5-8cm,中频高效——Lam 同款思路) |
| **带通 / 控制率** | **100-800Hz** / 16kHz |
| **滤波器 L** | **512**(中频 31Hz 分辨率够,算力减半) |
| **参考麦** | **窗外 1m**,朝噪声源;中频相干性**需实测**(阻塞项) |
| **预期** | 整窗能量平均 ~6-9dB(点测 ~10-15dB),参照 Lam 300-1000Hz ~10dB |

**代码改动清单(当前 PC 原型 → 12 单元嵌入式)**: 通道上限 `GFANC_E_MAX/S_MAX` 5/4→16/16;
带通 20-1500→**100-800Hz**;L 1024→**512**;`sub_filters` 按 S=12 重训;平台移植(R-21 HAL)。

## 5.3 分阶段路线

| 阶段 | 内容 | 目标 |
|---|---|---|
| **Phase-1(已完成)** | PC 原型:灵敏度/校准/125Hz/算法优化 | 验证算法能力(离线 13dB) |
| **Phase-1.5(硬件验证,必做)** | 实用麦选型(非 ECM8000,§4.7) + **中频相干性实测** + 1-2 个中频小喇叭对消验证 | **验证全部硬件假设**后才允许进入 Phase-2:麦灵敏度/SNR/相干性/对消可行 |
| **Phase-2** | DSP 最小系统:**12 扬声器+8 误差麦** + 2ms + 参考窗外 1m + 100-800Hz | 整窗 100-800Hz,能量平均 ~6-9dB(点测 ~10-15dB) |
| **Phase-3(可选)** | 扩到 20-24 单元 + 参考阵列 | 到 1000-2000Hz |

## 5.4 一句话总结

> 现代车外噪 = **中频胎噪(100-800Hz)**。前馈 ANC 消它靠**低延迟(≤2ms DSP)+ 密集小喇叭阵列(12 单元,21cm 间距)+ 窗外参考(相干性需实测)**——不靠低频大喇叭。
> 瓶颈在硬件(延迟/阵列/相干性),不是算法(离线已验证 ~15dB 能力)。
