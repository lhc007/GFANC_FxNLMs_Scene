## 1. 窗户开口的声学建模

### 1.1 窗户作为声学孔径

窗户开口的 ANC 问题本质上是**有限孔径的声传输控制**，与耳机（密闭腔体）或管道（一维传播）有根本区别：

```
室外噪声源 ──→ [窗户开口] ──→ 室内听音区
                  │
          参考麦(室外侧)  误差麦(室内侧)
                  │           │
              扬声器 ────→ 反噪声
              (窗框内侧)
```

**关键声学事实**：
- 窗户开口对低频（波长 >> 开口尺寸）表现为**二次声源**——开口处的声压分布近似均匀
- 对高频（波长 < 开口尺寸），开口处声场呈模态分布，单点控制失效
- 这意味着 ANC 的有效带宽受限于**开口尺寸与波长的关系**

### 1.2 当前系统的空间采样

| 参数 | 值 | 含义 |
|------|----|------|
| 扬声器数 (S) | 2 | 两个反噪声源 |
| 误差麦数 (E) | 3 | 三个控制点 |
| 系统总长 | ~50cm | 参考麦到最远误差麦的距离 |
| ANC 通带 | 20-1500Hz | 对应波长 17m(20Hz) ~ 0.23m(1500Hz) |

**空间采样分析**：

对于典型窗户开口（假设 1m × 1.2m）：
- **500Hz（波长 0.69m）**：窗户开口 ≈ 1.5λ × 1.7λ。在这个频率，开口处的声场需要至少 3-4 个控制源才能有效控制。2 个扬声器可能不足以覆盖。
- **1500Hz（波长 0.23m）**：开口 ≈ 4λ × 5λ。声场高度模态化，2 个扬声器 + 3 个误差麦几乎不可能实现全局控制。**1500Hz 作为通带上限是乐观的**——实际有效上限可能在 500-800Hz。
- **100Hz（波长 3.4m）**：开口 << λ。开口近似均匀声压，**单扬声器+单误差麦即可能有效**。2 扬声器 3 误差麦在此频段有冗余。

**⚠️ 这是当前系统架构中最大的未讨论假设**：2 扬声器 + 3 误差麦是否能覆盖整个窗户开口的 ANC 需求？当前代码对此没有建模或验证逻辑。

### 1.3 因果约束分析

```
声学延迟 = 参考麦→扬声器→误差麦 的传播时间
总延迟 = 声学延迟 + ADC/DAC + FIR群延迟 + DSP处理
```

| 延迟分量 | 时间 | 说明 |
|---------|------|------|
| 声学传播 (50cm, 参考→误差) | ~1.5ms | 声速 343m/s |
| ADC + DAC | ~0.5ms | 典型音频接口 |
| 带通 FIR 群延迟 (1024tap @ 16k) | ~32ms | `(N-1)/(2·fs)` |
| DSP 处理 (FxNLMS + 内插) | ~0.1ms | 可忽略 |

**总延迟 ≈ 34ms**

对于频率 f 的正弦波，34ms 对应的相位：
- **20Hz**：`34ms × 20 × 360° = 245°` → 相位余量 115°，仍可有效抵消
- **100Hz**：`34ms × 100 × 360° = 1224°` = 3.4 个完整周期。带宽内的因果约束已非常紧张。
- **500Hz**：17 个完整周期。**因果 ANC 几乎不可能**——系统更多依赖前馈预测而非实时响应。

**核心洞察**：当前系统的 32ms FIR 群延迟是因果 ANC 的主要瓶颈。对于 500Hz+ 的噪声，系统实际上工作在"预测"模式而非"响应"模式——CNN 场景分类 + Wc 预设提供了正确的初始相位，LMS 微调。**系统的降噪上限由声学延迟 + FIR 群延迟共同决定，而非算法本身**。

### 1.4 为什么离线 15dB → 实时 4-9dB？

离线仿真的 15dB 是在以下理想假设下达到的：
1. Ŝ 模型完美（仿真中 Ŝ = 真实 S）
2. 无因果延迟（仿真逐样本处理，无声学传播延迟）
3. 无传感器噪声
4. 无室内混响（离线路径用 Ŝ 域直接合成，实际声学路径包含多次反射）

实时 4-9dB 的损失来自：
1. **因果约束**（主因）：34ms 延迟使得 >200Hz 的实时抵消大幅退化
2. **Ŝ 模型误差**（次因）：未实测校准
3. **室内混响**：误差麦接收到的不仅是直达反噪声，还有墙面反射后的反噪声——这些反射分量相位随机，不可控
4. **声学解相关**：参考麦和误差麦之间的声场非完全相干（特别是高频）

**建议**：
- 定量测量各因素占比：分别测量 (a) 离线 Ŝ 域 NR (b) 在线 Ŝ 域 NR (c) 真实声学 NR。差异 (a)-(b) = 因果损失，(b)-(c) = 模型误差+混响损失
- 如果因果损失占主导（预期如此），考虑缩短 FIR（512 tap → 16ms 群延迟）以换取高频因果性，但会损失低频频率分辨率

## 2. 窗户安装的工程约束

### 2.1 参考麦克风的朝向

参考麦**必须朝向室外噪声源**。如果参考麦也接收室内反射声或扬声器串扰（反馈），参考信号被污染，ANC 会试图抵消"虚影噪声"，反而在室内制造噪声。

当前代码通过 `fb_fir` 反馈抵消缓解了扬声器→参考麦的直接串扰，但**室内反射声经墙壁再到达参考麦的间接串扰**没有被建模。这种间接串扰的路径长度不一，不能用简单的 256 tap FIR 抵消。

**缓解措施**：
- 物理层面：参考麦用指向性麦克风（心形/超心形），背对室内
- 信号层面：在参考麦后加挡板（声学隔离）
- 代码层面：当前未处理，建议在参考路径增加去混响滤波器

### 2.2 扬声器与误差麦的相对位置

**最佳布置原则**：误差麦应放置在扬声器的"声学近场"（距离 < 波长/2π ≈ 5cm @ 1kHz）内，以确保反噪声直达声远强于反射声。

当前代码假设：
- `抗噪声 = Wc ⊗ ref` 经扬声器播放后，误差麦收到的就是干净的 anti
- 实际上误差麦收到的是 `S_real ⊗ anti + 混响 + 室外噪声残余`

**⚠️ 代码中 F-A 修复后的实时路径**：梯度用 `err_meas` 直接驱动，err_meas 是 `bp(err_mic × GAIN)`，包含了上述所有分量。LMS 会自然地驱动 Wc 去抵消所有可预测的分量（包括混响中与 ref 相关的部分）。但混响中的非相干分量成为梯度噪声，降低收敛速度。

### 2.3 多窗户/大开间的扩展性

当前 MIMO 配置 (E=3, S=2, L=1024) 是针对单窗户开口设计的。如果未来需要覆盖：
- **多个窗户**（如一排窗户）：每个窗户需要独立的参考麦 + 误差麦 + 扬声器组
- **落地窗/推拉门**（大面积开口）：需要更多扬声器和误差麦

当前代码的 E、S、L 通过 `#define` 可配置，但：
- `scene_controller.c` 硬编码了 SC_S=2（扬声器数），SC_C=15（子滤波器数）
- `howling_detect.h` 硬编码了 HW_S=2
- MIMO FxNLMS 的计算量是 O(E×S×L)，当前 E=3, S=2, L=1024 = 6144 MAC/样本。如果 S=4, E=6 则变为 24576 MAC/样本（4×）

**建议**：在 `gfanc_types.h` 中集中定义通道数，并通过编译期常量传播到所有模块。

## 3. 验证阶段 → 量产阶段的差距分析

### 3.1 当前验证缺失项

| 验证项 | 状态 | 窗户 ANC 特定要求 |
|--------|------|-------------------|
| 次级路径 Ŝ 实测 | ❌ 未做 | 需在真实窗户开口测量 E×S=6 条路径 |
| 初级路径 Pri 实测 | ❌ 未做 | 需在窗户开口测量参考→各误差麦的传递函数 |
| 反馈路径 Fb 实测 | ✅ 已做 | 逐扬声器，但校准时窗户状态（开/关）未记录 |
| 因果性定量测量 | ❌ 未做 | 参考-误差互相关 → 声学延迟 + 相干函数 |
| 声场空间采样 | ❌ 未做 | 移动到不同位置验证 NR 的空间均匀性 |
| 环境鲁棒性 | ❌ 未做 | 温度/湿度/风速对系统性能的影响 |

### 3.2 量产前的必须验证

1. **空间降噪均匀性测量**：在窗户开口平面上以网格方式（如 10cm 间距）测量 NR，绘制 NR 空间分布热力图。确定当前 2S+3E 配置的有效覆盖区域。

2. **因果性测试**：
   - 播放 MLS（最大长度序列）信号经扬声器 → 互相关辨识从扬声器到每个误差麦的完整声学路径
   - 同时辨识参考麦到误差麦的初级路径
   - 计算 `min(延迟_S) - max(延迟_Pri)` —— 如果为负，因果 ANC 不可能

3. **混响影响量化**：
   - 测量窗户开口处的 RT60（混响时间）
   - 如果 RT60 > 100ms @ 500Hz，室内混响严重限制高频 ANC

4. **长期稳定性**：
   - 24 小时连续运行测试，监控 NR、Wc 系数漂移、freeze_lms 触发次数
   - 温度循环测试（如 5°C ~ 40°C），验证 mic_pre_gain 和次级路径的温度依赖性

### 3.3 量产硬件方案评审

UPGRADE_ROADMAP 中的三套量产方案是合理的技术路线。补充几点：

**方案 B (ARM Linux 定制板, RK3566) — 关键审视**：

1. **ADC 选型 (PCM1865)**：110dB SNR 是足够的。但 4 通道对于 E=3 误差麦 + 1 参考麦刚好用完。无扩展余量。建议选 6-8 通道 ADC（如 PCM1864 的 4ch → 换成 8ch 版本），为未来 S/E 扩展留硬件余量。

2. **DAC 选型 (TLV320AIC3254)**：内置 miniDSP 可用于实现抗混叠/抗镜像滤波（P-1/P-2），卸载 CPU。但只有 2 通道输出——如果要扩展 S>2，需要额外 DAC。

3. **NPU (RK3566 内置 0.8 TOPS)**：CNN 推理 ~8ms 在 CPU 上。如果移植到 NPU，推理时间可降至 <0.5ms。但 RK3566 的 NPU 主要面向视觉模型（INT8），M5 音频 CNN 的卷积核较大（k=80），可能不是 NPU 的最佳匹配。建议提前做 NPU 移植可行性测试。

**方案 C (Qualcomm QCC5181) — 关键审视**：

1. **定点移植**：当前所有代码使用 float32。QCC5181 的 DSP 是 24-bit 定点。移植需要：
   - FIR 从 float32 转 int32（Q31 格式）
   - CNN 从 float32 转 int8（量化，精度损失）
   - IIR 陷波器系数从 float 转定点（需用 DF1/D2T 结构防极限环）

2. **量化精度损失评估**：
   - FIR：int32 累加 1024 tap 可能有 ~48 bits 的动态范围，截断回 24 bits 会引入量化噪声。需要在量化前做仿真验证。
   - CNN：int8 量化通常有 <3% 精度损失。但 M5 的 maxpool + ReLU 对量化友好程度需要实际测量。
   - NLMS 梯度：float32 → fixed24 的梯度截断可能造成"梯度消失"（小梯度被截断为 0）。需要引入梯度随机舍入（stochastic rounding）。

3. **内存约束**：QCC5181 的内部 SRAM 可能在 512KB-1MB 级别。当前系统（含 1MB CNN 静态缓冲 + 600KB CNN 权重）可能超预算。需要：
   - CNN 权重从 float32 压缩到 int8 → 150KB
   - Xd[E×S×L] = 6144 float → int16 → 12KB
   - 静态缓冲复用而非持久分配

## 4. 算法对窗户 ANC 的适应性

### 4.1 前馈 vs 反馈：窗户场景的选择

当前系统是**纯前馈** ANC（反馈 IIR B-1 未实现）。对于窗户降噪：
- **前馈**处理室外传来的噪声（可预测——参考麦先听到）
- **反馈**处理室内产生的噪声（不可预测——无参考信号）

窗户 ANC 的理想架构是**前馈为主，反馈为辅**：
- 前馈抵消从窗户传入的室外噪声（主任务）
- 反馈提供 20-200Hz 低频补充（前馈因果性最弱的频段）

当前 B-1 未实现意味着低频段完全依赖前馈。对于 20-100Hz 噪声（波长 3.4-17m），前馈的因果约束最宽松（1.5ms 声学延迟 << 10ms 周期），前馈应该是足够的。**B-1 的缺失对窗户应用的影响可能比预想的要小**——但对室内突发噪声（如敲门、说话）完全没有控制能力。

### 4.2 CNN 场景分类的窗户噪声适应性

8 类场景（由 Python 训练数据决定）对窗户 ANC 的覆盖程度是未知的。可能的窗户噪声场景：
- 道路交通（宽带，低频为主）
- 施工噪声（冲击性，间歇性）
- 风声（非平稳，宽带）
- 人声/音乐（从室外传入）
- 雨声（高频宽带）

**⚠️ 建议**：检查 `data/scene_defs.bin` 中 8 个 centroid 的实际含义。打印每个 centroid 的 30 维 blend 权重，分析对应哪些子滤波器，推断场景类型。如果训练数据不包含窗户典型噪声，CNN 分类准确率会退化，影响 Wc 初始值的质量。

### 4.3 啸叫检测在窗户场景的特殊性

窗户 ANC 的啸叫风险比耳机 ANC **更低**：
- 耳机：扬声器→麦克风距离 < 2cm，反馈路径增益高
- 窗户：扬声器→参考麦距离 ~50cm，且参考麦朝向室外（背对扬声器）

因此当前 15dB 阈值可能对于窗户场景过于敏感。但保留是安全的——宁可误检（加陷波）也不可漏检（啸叫损坏听力/硬件）。

## 5. 针对窗户 ANC 的优先级重排

基于以上分析，对原综合审查报告中的优先级进行窗户 ANC 视角的重新排序：

### 🔴 验证阶段必须完成（阻塞量产决策）

| 项目 | 原因 |
|------|------|
| **空间 NR 均匀性测量** | 确定 2S+3E 是否足够。如果不够，E/S 扩展需在硬件设计阶段考虑 |
| **因果性测试（互相关）** | 确定系统有效带宽上限。如果 >500Hz 因果性不成立，可降低 FIR tap 数（1024→512）改善因果性 |
| **次级路径实测校准 (F-B)** | 消除 Ŝ 模型误差，缩小离线/在线 NR 差距 |
| **窗户开口声场测量** | 确定混响 (RT60) 和环境噪声基底 |

### 🟡 量产前必须完成

| 项目 | 原因 |
|------|------|
| 跨线程同步修复 (§6.2) | ARM 移植前提 |
| int8/int32 量化仿真 | Qualcomm 路径的前提验证 |
| 24h 长期稳定性测试 | 量产可靠性 |
| 温度循环测试 | mic_pre_gain 和 Ŝ 的温度依赖性 |

### 🟢 可延后到量产之后

| 项目 | 原因 |
|------|------|
| 事件驱动状态机 (A3) | 提升可维护性，不影响核心功能 |
| 可变步长 NLMS (B1) | 当前固定步长已稳定工作 |
| 在线反馈抵消自适应 (B4) | 窗户场景反馈路径相对稳定（无接触、无移动部件） |

> **总结**：从窗户 ANC 的视角审视，当前代码的核心架构（前馈 MIMO FxNLMS + CNN 场景分类）是合理的。最大的不确定因素不在代码中，而在**声学物理层面**——2 扬声器 + 3 误差麦是否能有效覆盖目标窗户开口的空间范围？32ms FIR 群延迟是否吃了太多因果裕度？这些问题的答案需要通过**硬件在环的声学测量**来获得，而非代码审查能回答的。
