【R-50 反馈路径 spk1 校准极弱 · 建议 · [Phase-1] → 🔒 PC 测试台暂弃反馈对消（2026-08-13）】
- **位置**：data/feedback_path_0/1.bin
- **问题描述**：旧 spk1 FIR RMS≈2e-5 太弱。
- **修复方案**：2026-08-03 `GFANC_CAL_NOISE=1.5` 重标定（RMS 0.0012/0.0011）。
- **验证方法**：重标定后加载成功；但 **spk0 峰@tap224(14ms) 疑似噪声伪峰**（反馈耦合仅 -40dB 级，NLMS 拟合多为噪声）。
- **修复状态**：🔧 已重标定（通过 0.00005 门禁）；**2026-08-12 加峰位物理 sanity 门禁（WARN 不拒收）**——`calibrate_feedback.c` 对峰位 >11ms（物理上限=全环路 12.4ms 的 spk→ref 子集）打 ⚠ 提示。数据依据：四份反馈 FIR PNR 均仅 4-5（噪声拟合），但峰位按工具分化——calibrate_secondary（逐块对齐）4.9-7.9ms vs calibrate_feedback（无对齐）13.6-14.4ms → 14ms 更可能是**流对齐残留**而非纯噪声，运行时已加载此类文件故不拒收（拒收会清空现有反馈抵消）；另输出 PNR 便于人工判断。影响小（FB est 0.001-0.010）。窗户安装后需重跑。
- **🔒 2026-08-13 决定：PC 测试台暂时放弃反馈对消**（反馈文件已改名 `data/feedback_path_{0,1}.bin.disabled`，运行时自动跳过；Test A 反馈关 = 当前稳定配置：250Hz 纯音 err 稳定 0.044 / 零 rescue / 零 QUIET 误触发）。
  - **起因**：2026-08-13 三处改动（FB_TAPS 256→512、聚类投票延迟验证、R-50 改窗口边沿拒收）后重标定 + 反馈开启跑 250Hz 实机——**仍发散**：4 次 rescue + 3 次 peak_mute + err 0.04-0.32 振荡 + anti 涨到 0.7 + 滋滋声。Test A（反馈关）对比稳定。
  - **冒烟枪 = FIR 低频超估 ~4×**：新 FIR（512tap、峰@236/240=14.75/15ms、聚类 9/9 通过、不再贴边截断）在 250Hz 增益 **0.38/0.71**、125Hz **0.86/0.99**（低频被严重抬高）；而运行时 raw_ref 0.058 / anti 0.35 → 真实 250Hz 反馈增益 ≈ **0.17** → 超估约 4×。
  - **发散链**：anti↑ → fb_est=0.71×anti↑ → 压过 raw_ref(0.058) → AGC（main_realtime.c:276-282）把残差误当"ref 过强" → ref_clean 被衰减到 0.06 且翻相位 → err_ref=err/ref_clean 虚高到 4.57 → **rescue 全是假触发**（rollback+ramp 反复打断收敛）→ ref_clean 变弱 → FxLMS 压不下 err → anti 涨到 0.7 → 输出饱和 peak_mute → 滋滋声 = 高驱动失真 + rollback 宽带杂散。
  - **根因**：反馈 NLMS 本身没收敛（无逐块对齐、不报 ERLE，max|err| 平 0.33-0.41 = 64000 样本单样本最大峰，对白噪声天然大，非收敛指标），把低频/直流分量烤进系数。**"截断修好 ≠ 系数修好"**。另：R-50 旧"11ms 物理上限"假设本就不对——USB 设备往返 ~12ms 就在反馈路径里，峰@14.75ms 是真实延迟。
  - **已生效**：QUIET 的 err_ref 门（quiet_err_ref=1.5）——本次音源开着全程零误触发，QUIET 只在噪声真停时触发（err_ref 分离"深对消纯音 0.7-1.1"与"噪声真停 ≈2.4"）。
  - **2026-08-13 追加发现（反馈关复测，参考麦 CLIP 饱和）**：反馈关掉后 250Hz 复测大部分稳定（err 收敛到 0.044 持续 ~12s），但用户观察到**参考麦 CLIP 灯随运行时间逐渐亮**——单独放 250Hz 不亮、系统刚启动不亮、anti 涨到稳态 0.43 后逐渐亮。机制：参考麦在扬声器近场，稳态 anti 的扬声器输出（声学反馈，增益≈0.17×anti）把参考麦模拟输入推到饱和 → 限幅=参考信号非线性失真 → 污染 FxLMS 参考 → cb 12067 err 0.074→0.193 跳变 + rescue。**此问题与反馈对消无关**（反馈关着也发生），是"参考麦在扬声器近场"的几何结构在模拟域的直接体现，也是 Test A 若跑久也会遇到的慢燃发散源。**处理**：参考麦（UMC 输入 1）旋钮降 ~一半 + `GFANC_MIC_GAIN=2.0` 数字补偿（ref_rms 在 mic_pre_gain 之后累加，err_ref/QUIET 阈值保持一致；调低参考麦增益同时压低反馈分量，一石二鸟）。
  - **恢复方法**：`mv data/feedback_path_0.bin.disabled data/feedback_path_0.bin`（0/1 各一次）即恢复反馈。
  - **若以后要做（嵌入式 8spk/6mic 样机反馈是刚需）**：① 逐块对齐 NLMS（移植 calibrate_secondary 的 build_aligned，±70→±3 样本涂抹压缩）；② ERLE 收敛验证达标才保存；③ 窄带/白化激励标定（白噪声被扬声器低频主导，烤出 LF 假增益）；④ 参考麦高通去直流；⑤ 复核 AGC 基于残差与反馈开启的耦合。

### 低优先级一致性项（2026-08-17 通读，待决定，均不阻塞）

【N-1 wc_init_max RESET 后未重标定 · 低】

## 六、架构结论与升级路线

- **双环路设计正确**：慢环路（CNN 1Hz 设 Wc 起点）+ 快环路（FxLMS 16kHz 自适应）——CNN 是"暖启动"，即使场景判断慢/错，FxLMS 持续追当前噪声。
- **算法内核**（FxNLMS/CNN/Blend/陷波/校准）公式级复核全部正确。
- **关键认知**：实时 NR 上限由**因果性**（控制路径 ~10.8ms，64tap 带通后净预览 ≈−9ms vs 1.9ms 预览）决定，不是 CNN 场景识别速度。
- **前馈+反馈互补**：前馈消窄带/周期/低频；反馈（B-1）补低频宽带。**PC 阶段不值得**（稳定带 20-30Hz 无噪声能量）；**嵌入式（2ms 环路）补 20-200Hz** 才有 +3-4dB。

|------|------|--------|
| **Phase-1（PC，当前）** | 算法验证 | ✅ 全部纯 C 修复；⏳ 窗户重测 Ŝ+反馈；⏳ 黄金基线 |
| **Phase-2（RK3566 ARM）** | 脱离 PC | R-21 HAL、R-19 atomic、低延迟反馈 |
| **Phase-3（QCC5181/SHARC）** | 量产 | R-23/22/25、定点化 |
