# 因果性限制与窗户 ANC 可行性 — 参考笔记

> **日期**: 2026-08-03
> **背景**: 针对"系统能否对宽带马路噪声达到 10dB 降噪"的深入讨论。核心问题是**前馈 ANC 的因果性（预览时间）**如何决定实时降噪上限，以及窗户 ANC 论文（Lam et al. 2020）为何能做到 10dB 而当前系统不能。
> **用途**: 供后续硬件/架构决策参考。与 [GFANC_综合审查报告_合并版.md](GFANC_综合审查报告_合并版.md) §物理层瓶颈 配套。

---

## 1. 核心概念：预览时间（causality / preview time）

前馈 ANC 能否抵消宽带随机噪声，由**预览时间**决定：

```
预览时间 = 参考麦→误差麦声学延迟 − (处理链延迟 + 扬声器→误差麦声学延迟)
```

- **预览时间 > 0** → 参考麦提前听到噪声，控制器有"提前量" → 宽带可实时对消（频率上限受预览大小限制）。
- **预览时间 < 0** → 反噪声比噪声晚到误差麦 → 对随机宽带噪声不可对消（只能消窄带/周期 + 部分低频）。

**当前系统实测值**：

| 分量 | 值 |
|------|-----|
| 参考→误差声学延迟（64cm / 343） | +1.9ms |
| ANC 带通群延迟（256tap） | −8ms |
| **声卡环路延迟**（UMC ASIO，**128 样本缓冲**，实测） | **−12.4ms** |
| 扬声器→误差声学延迟（15cm） | −0.44ms |
| **净预览** | **≈ −18.5ms** |

> ⚙️ **2026-08-03 缓冲修复**：原 `suggestedLatency=0.01`（10ms）把 ASIO 驱动顶到 512 样本 → 环路 **30.44ms**（预览 −28ms）。改 `GFANC_BUFFER=128` + 延迟由缓冲推导后，环路 **12.38ms**（预览 −18.5ms）。预览仍为负（宽带中高频仍不可实时对消），但低频可控范围明显变宽。
>
> −18.5ms 意味着：反噪声到达误差麦时，噪声已过去 ~18.5ms。对随机宽带噪声（相关时间 < ~18ms，即 > ~55Hz 的成分），不可实时对消；<55Hz 宽带 + 窄带/周期成分可消。

## 2. 两种"延迟"不能混淆

| 延迟 | 值 | 有没有问题 |
|------|-----|-----------|
| **CNN→Wc 交接**（慢环路，1Hz） | 1 秒 | ✅ **无问题**——CNN 是"暖启动"（提供 Wc 起点），FxLMS 每样本持续追当前噪声，场景判断慢/错不影响最终收敛 |
| **前馈处理链**（快环路，每样本） | **12.4ms** | ❌ **这才是问题**——反噪声到达时间被物理链路锁死，与 Wc 无关 |

**关键认知**：Wc（控制滤波器）只决定反噪声的**形状**（频率/相位），**不决定它的到达时间**。无论 Wc 多准、场景判断多快，反噪声都要走 12.4ms 处理链。场景降噪能帮的是"可预测"的噪声（窄带/周期/缓慢变化），对随机宽带无用。

**类比**：音乐会机器，知道"这是爵士乐"（场景）能帮你调好 EQ（Wc 更准），但没法预知下一个即兴音符（宽带随机）——12.4ms 处理意味着听到上一个音符时机器还在处理它。

## 3. 窗户 ANC 论文对照（Lam et al. 2020, Scientific Reports）

论文在 1m×1m 全尺寸家用窗上实现了 **7.51-10.14 dB**（能量平均 SPL）的真实宽带城市噪声（公路/高架 MRT/飞机）降噪。但它做到 10dB 的条件与当前系统**根本不同**：

| 条件 | 论文 | 当前系统 |
|------|------|---------|
| 扬声器数 | **24 个** 4.5cm 小扬声器铺满窗洞 | **2 个** MR4 |
| 误差麦 | 运行时**不装**（离线 FxLMS 训练固定 FIR，运行时直接播放） | 3 个误差麦，持续自适应 |
| 参考麦 | 单个，放在**窗户外侧**（朝噪声源，提供提前量）；测试声源在窗外 **2m**；参考麦到窗户的**精确距离论文未明示** | 1 个，距误差麦 64cm（1.9ms） |
| 控制器 | 实时 **DSP，~ms 级低延迟** | PC + UMC 声卡，**12.4ms 环路** |
| 控制频段 | **300-500Hz**（论文原文："little active control below 300 Hz, restricted between 300-500 Hz"——小扬声器低频效率低） | **<300Hz**（因果性允许的低频）+ 全频段窄带 |
| 方法 | 固定滤波器 + 空间阵列（24 源控制窗洞声场） | MIMO FxLMS 自适应（2 源 + 3 点） |

**为什么论文能、当前系统不能**：

```
论文: 预览(窗外远处 3-6ms) − (DSP ~2ms + 扬声器→误差 ~0.5ms) = 余量正 → 300-500Hz 可控
当前: 预览(1.9ms) − (12.4ms + 0.44ms) = −18.5ms → 中高频宽带不可控
```

**决定性差异 = 那 12.4ms 声卡延迟。** 论文用低延迟 DSP，PC 声卡把因果性吃光了。

**注意两点**：
1. 论文的 10dB 是**中频段（300-500Hz）**，<300Hz 几乎没控制（小扬声器限制）——与当前系统（控低频）正好**互补**，不是"全频段 10dB"。
2. 论文用 **24 通道**做**空间声场控制**（让窗洞成为声压释放边界），这是 2 扬声器无法做到的。

**关于参考麦距离**：论文将单个参考麦放在**窗户外侧**（朝噪声源），测试声源（播放录制噪声的扬声器）在窗外 **2m** 处；但**参考麦到窗户平面的精确距离论文正文未明确给出**（示意图 Figure 1 展示了位置但尺寸不可靠解读）。关键点：论文能控 300-500Hz 靠的是**低延迟 DSP（~1-2ms）+ 参考麦在窗外（即使窗外 0.5-1m 也有 ~1.5-3ms 预览）**，而非把参考麦放得特别远。**当前系统参考麦 64cm（1.9ms 预览）并不算短，被 12.4ms 声卡延迟拖垮——决定性差异是延迟，不是参考麦距离。**

## 4. 结论与路线含义

**结论**：
1. **窗户 ANC 概念可行，10dB 宽带降噪是真能拿到的**——但前提是低延迟 DSP + 多通道阵列 + 参考麦放窗外远处。
2. 当前 PC 原型（2 扬声器 + 12.4ms 声卡）**无法复现论文效果**：因果缺口 −18.5ms 决定了中高频宽带实时不可消，能消的是 <300Hz 低频 + 窄带/周期成分（实测误差麦处 ~13dB 主要来自这些）。
3. 宽带"声压→0"的目标在当前拓扑 + PC 延迟下不可能；需嵌入式低延迟 + 足够通道。

**达成论文级效果的路径**（对应 roadmap）：

| 杠杆 | 作用 | 阶段 |
|------|------|------|
| **低延迟控制器**（RK3566/QCC5181） | 12.4ms → ~1-2ms，预览变正，中频宽带开始可控 | Phase-2/3 |
| **更多扬声器**（论文 24 个） | 空间声场控制（4 个是起步，控全窗洞偏少） | 硬件扩展 |
| **参考麦放窗外远处** | 增大预览（64cm→2-3m） | 安装几何 |
| **带宽现实化** | 论文 10dB 在 300-500Hz；修好延迟后 <300Hz 宽带 + 全频段窄带 | 期望管理 |

**一句话**：场景降噪 + 一点延迟对可预测噪声完全没问题；对随机宽带，物理上消不动的是"到达时间"而非"滤波器精度"——解决它靠**低延迟 + 多通道**，不靠更好的 CNN。
