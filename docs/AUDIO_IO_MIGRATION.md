# 音频 I/O 栈问题分析与单时钟设备迁移指南

> 日期：2026-07-16
> 关联：[CODE_REVIEW.md](CODE_REVIEW.md) F-B 项 | [UPGRADE_ROADMAP.md](UPGRADE_ROADMAP.md)
> 结论先行：**当前"YDM6MIC + USB 扬声器"双独立时钟设备栈存在 73ms 环路延迟 + 1500~1900ppm 流滑移，
> 物理上无法支撑自适应 ANC。软件已修复所有算法层问题并配齐保护机制，剩余瓶颈只能靠更换
> 单时钟音频接口解决。**

---

## 1. 症状

- F-A（实时 FxNLMS 信号结构错误）修复后，系统启动即发散：扬声器满幅输出（啸叫），
  保护机制介入后表现为"啸叫 ~0.5s → 静音 → 再啸叫"循环。
- 次级路径校准（calibrate_secondary.exe v1~v3）反复失败：辨识 ERLE ≈ 0dB，
  系数为噪声级。

## 2. 排查时间线与测量证据

| 步骤 | 手段 | 结果 |
|---|---|---|
| 校准 v1（盲 NLMS，64ms 窗口） | 1024-tap NLMS 直接辨识 | ERLE=-0.5dB，peak 位置随机 → 判定"未捕获响应" |
| 声学回路验证 | 扬声器音量开/关对比录音 RMS | ch2: 0.0072（开）vs 0.00044（关），**降 15 倍 → 回路正常，SNR≈24dB，麦克风灵敏度非主因** |
| 校准 v2（3s 长窗互相关） | 0~2s 全程扫 lag | PNR≈5（噪声边缘），峰位置随机 → 长窗相关被滑移涂抹 |
| 校准 v3（0.5s 分段短窗） | 4 段独立找峰 | **真峰出现**：1229/1266/1280/1296（77~81ms），段间走差 +14~37 样本/秒；但单窗 PNR 仅 5~11，时有时无 |
| 流参数实验 | 96帧/2ms → 960帧/0.2s | 小缓冲下滑移达 ~7000 样本/秒（成块跳变）；大缓冲降到 ~25 样本/秒（平滑漂移） |
| 校准 v4（聚类投票 + 逐块对齐） | 17×0.25s 子窗投票；0.125s 逐块跟踪对齐后 NLMS | **探测 17/17 全聚类**，延迟 78.1ms、滑移 1484~1917ppm 实锤；对齐后 IR peak 精确落在预期位置（tap 64），但 **ERLE 仍 ≈ 0** |

### 最终测量结论（22=YDM6MIC WASAPI，18=USB Speaker WASAPI，960帧+0.2s）

| 量 | 值 |
|---|---|
| DAC→ADC 环路延迟 | **~78ms**（bulk 1171 样本 @16k = 73.2ms + 声学/保护余量） |
| 流滑移（时钟不同步） | **1484~1917ppm**（24~31 样本/秒，平滑漂移，随会话变化） |
| 麦克风耦合电平 | 激励 0.9 时误差麦 ~0.013 RMS；房间底噪 ~0.0005 |

## 3. 三个物理事实（根因）

1. **因果性**：前馈 ANC 要求"噪声从参考麦传到误差麦的声程时间 > 系统环路延迟"。
   73ms 对应声程 **25 米**，窗户场景实际只有 <1m（~3ms）→ **宽带随机噪声无法抵消**，
   与算法无关。周期性噪声不受此限（可预测性替代超前性）。
2. **白噪声 1 样本去相关**：白噪声自相关是脉冲，错位 ≥1 样本相关即归零。
   滑移 25 样本/秒 → 信号仅在 **~40ms** 内保持 ±0.5 样本对齐 →
   系统在 16k 采样格点上每 40ms 就"不再是同一个系统"（非 LTI）。
   1024-tap NLMS 需 ~0.3s 收敛，期间 IR 已挪 8 个 tap → 只能学到涂抹近零的平均。
   这解释了"peak 位置正确但 ERLE≈0"。
3. **自适应稳定界**：FxLMS 要求 Ŝ 与真实 S 的相位差 <90°。滑移使对齐每秒偏移
   25~30 样本 → 即使 Ŝ 瞬时完美，500Hz 处相位每秒转 340°+ → 中高频必然发散；
   100Hz 处 ~1.1rad/s，自适应勉强可跟踪。

### "啸叫-静音循环"的机制

Ŝ 相位在大部分频带不可信 → 环境宽带声激励下 Wc 在 ~1s 内发散 → 输出满幅（啸叫）
→ 削波保护 50ms 后静音 → 1s 发散刹车回退 CNN 预设 Wc + 400ms 渐入 → 再次发散。
保护机制按设计工作，根因是 Ŝ 失配。

## 4. 已排除的因素

| 因素 | 证据 |
|---|---|
| 麦克风灵敏度（-26dBFS） | 开/关对比 SNR≈24dB，足够辨识；只是次要因素 |
| 声学回路断路 | RMS 降 15 倍验证回路通 |
| 算法结构（F-A） | 修复后经 tools/verify_fa.c 闭环仿真验证：旧结构 -14.6dB（放大），新结构 +11.4dB（SISO） |
| 设备选择错误 | MME/WASAPI/ASIO4ALL 多组设备结果一致 |

注意：**ASIO4ALL 不解决问题**——它只是聚合包装，两台设备仍各用各的晶振，滑移不变。

## 6. 硬件方案

**推荐：单时钟 USB 音频接口（4 输入 + 2 输出，同一晶振）**

- 例：Behringer UMC404HD（4in/4out，ASIO，~¥600-900）+ 4 只驻极体/测量麦
- 效果：滑移 **归零**（同晶振），ASIO 延迟 **5-10ms**
- 布放增益：参考麦伸出窗外朝噪声源方向 2m ≈ 挣回 6ms 声学超前 →
  因果裕度公式：`可抵消宽带 ⟺ 参考麦超前距离(m) ≥ 343 × 环路延迟(s)`
- 对标论文级宽带效果则需 1-3ms 延迟（树莓派+专用 ADC/DAC 或 DSP 板），可作二期

## 7. 单时钟设备迁移清单（代码适配）

### 7.1 必改项

| # | 位置 | 现状 | 改为 |
|---|---|---|---|
| 1 | `main_realtime.c` 输入通道数 | `PaStreamParams in_p = { in_dev, 6, ... }`，采样索引 `in[(n*3)*6 + c]`（c=0..3） | 接口是 4 通道则 6→4：建议先抽 `#define IN_CH 6` 再全局替换（共 2 处代码 + 1 处参数） |
| 2 | `src/calibrate_secondary.c` 输入通道数 | `in[i*6 + c]`、`in_p` 通道数 6 | 同上（与 #1 保持一致） |
| 3 | 设备选择 | 输入/输出分别选两个设备 ID | ASIO 接口为**单一全双工设备**：in_dev = out_dev = 同一 ID |
| 4 | 流参数（两处必须一致改） | 960 帧 + 0.2s latency（WASAPI 抗滑移妥协值） | ASIO 恢复低延迟：`framesPerBuffer 96~192`（保持能被 3 整除：96/192/384），`suggestedLatency 0.005~0.01`。**`main_realtime.c` 与 `calibrate_secondary.c` 必须同值**（bulk 延迟是流配置的函数） |
| 5 | `MIC_PRE_GAIN`（main_realtime.c:29） | 10x（按 YDM6MIC 整定） | 接口有硬件增益旋钮：先把模拟增益调到安静房间 RMS≈0.001~0.01，再按需设 1~5x 数字增益 |

### 7.2 迁移后重校准流程（顺序执行）

```bash
# 1. 重新编译（如改了 IN_CH / 流参数）
make all

# 2. 次级路径校准（预期指标见 7.3）
./calibrate_secondary.exe        # 单设备: 输入输出同一 ID

# 3. 运行验证
./gfanc_realtime.exe             # 应显示 "Secondary path: MEASURED (bulk=~100-500 样本)"
```

旧的 `data/secondary_path_measured.bin`、`sec_bulk_delay.bin`、`feedback_path*.bin`
换硬件后全部作废，由第 2 步重新生成（成对校验会自动处理）。

### 7.3 迁移成功的验收标准

| 阶段 | 指标 | 合格值 |
|---|---|---|
| 校准-探测 | 聚类比例 | ≥15/17 子窗聚类 |
| 校准-探测 | **滑移** | **<20ppm（关键指标，单时钟应≈0）** |
| 校准-探测 | 流启动延迟 | 100~500 样本（6~30ms，视缓冲设置） |
| 校准-辨识 | **ERLE** | **>15dB（滑移归零后应大幅回升）** |
| 校准-辨识 | 同扬声器 3 只误差麦 peak 延迟 | 彼此相差 <10 样本（相邻麦物理一致性） |
| 运行 | DIVERGE / 削波保护 | 不触发 |
| 运行 | 低频周期噪声测试（100Hz 正弦） | err 持续下降，NR 转正 >5dB |
| 运行 | 宽带测试 | 视参考麦超前距离；不达因果条件时宽带 NR≈0 属预期 |

### 7.4 无需改动的部分

- FxNLMS 实时结构（`fxnlms_tick_rt`/`fxnlms_forward_rt`）—— F-A 修复后与硬件无关
- bulk 延迟环形缓冲 —— 自动加载新的（更小的）bulk 值
- 发散刹车、削波保护、safety_mute —— 保留作为安全网
- 啸叫检测、CNN 场景环路、场景记忆
- calibrate_secondary v4 的投票/对齐逻辑 —— 滑移为零时轨迹平坦，自动退化为普通辨识

### 7.5 迁移后可继续的审查项（CODE_REVIEW.md）

硬件就绪后按优先级继续：

1. **B-2（高）**：啸叫陷波状态跨扬声器串用 —— 尚未修复
2. **F-G/F-F（中）**：每扬声器独立反馈抵消 —— v4 已产出 `feedback_path_s0/s1.bin`（对齐版），
   运行时需接入 bulk 延迟 + 双 FIR
3. **§6.1（高）**：`fir_tick` 取模消除 + `xd` 环形化 —— ASIO 小缓冲下回调预算更紧，此项变得必要
4. **§6.2（高）**：主线程/回调无锁交接
5. P-1/P-2（中）：重采样抗混叠/抗镜像滤波

## 8. 留在当前硬件的替代路线（不推荐）

若暂不购置硬件，理论上可做"亚样本重采样校准 + 运行时延迟锁环（DLL）"：
持续估计滑移率并对参考信号做分数延迟重采样。工程量大（相当于自研一个
音频时钟恢复子系统），且上限仍是 <150Hz 周期噪声、锁定易失。结论：投入产出比
远低于 ¥600 的硬件方案，仅作备忘。
