# 8×8 实时性验收预算表（算力 / 带宽 / preview / 相干性）

> **用途**: 阶段 1 开发板的**验收基准**——上板前用静态预算定"必须达到的线"，上板后逐项实测比对。
> **配置**: S=8 扬声器 / E=8 误差麦 / 1 参考麦 / L=1024（可降 512）/ SEC_LEN=1024 / Fs_anc=16kHz（62.5µs/tick）。
> **参考麦距误差麦**: 1m（preview = 2.92ms）。
> **独立分析（2026-08-21）**: 数字从 [src/fxnlms_mimo.c](../src/fxnlms_mimo.c)、[main_realtime.c](../main_realtime.c) 代码逐模块数出，不依赖历史文档。

---

## 0. 一句话结论

**8×8 实时性成立的前提 = NEON + L≤512 + 关在线Ŝ（或 RK3588）+ 低延迟 codec（ADC+DAC <100µs）。** 四个条件缺一不可。RK3568 满足前三个后，算力余量 2-3 倍；preview 余量 ~1.8ms。1m 参考距离的因果性够，相干性需实测（见 §4）。

## 1. 算力预算（确定性，静态可算准）

### 1.1 逐模块 MAC（8×8，L=1024，每样本）

| 模块 | 公式 | MAC/样本 |
|---|---|---|
| anti = Wc⊗x_hist | S×L = 8×1024 | 8,192 |
| Fx = Ŝ⊗ref（xd 更新） | E×S×SEC_LEN = 8×8×1024 | 65,536 |
| 功率 Σxd² | E×S×L = 8×8×1024 | 65,536 |
| 梯度更新 | E×S×L = 8×8×1024 | 65,536 |
| leak | S×L | 8,192 |
| Fx 带通（R-58-10，独立 FIR/路径） | E×S×256 | 16,384 |
| err 带通 | E×256 | 2,048 |
| ref 带通（CNN 1024 + ANC 256） | 1024+256 | 1,280 |
| 反馈抵消 | S×FB_LEN(512) | 4,096 |
| 杂项（AGC/EMA/钳位/VS-LMS） | — | ~500 |
| **前馈小计** | | **~237,300 → 3.80 GMAC/s** |
| 在线 Ŝ 辨识（sec_online_update，默认开） | S×L + 2×E×S×L | +139,264 → **+2.23 GMAC/s** |
| **总计（开Ŝ）** | | **~6.0 GMAC/s** |

### 1.2 RK3568（4×A55）对照

| 执行方式 | 吞吐 | 前馈 3.8 GMAC/s | 开Ŝ 6.0 GMAC/s |
|---|---|---|---|
| 标量 FP32（1 FMA/cycle/核） | 1.8 GMAC/s/核 | **2.1 核** ❌ | 3.3 核 ❌ |
| NEON 单核（2×128-bit FMA）理论 | 14.4 GMAC/s | 26% | 42% |
| NEON 单核实际（效率 50-70%） | 7-10 GMAC/s | **38-54% 负载** ✅ | **60-86%** ⚠️ |
| NEON + L=512（全部减半） | 同上 | **19-27%** ✅ | **30-43%** ✅ |

### 1.3 算力验收线

- ✅ **达标**: 上板实测 8×8+L1024 单 tick < **62.5µs**（预算 100%），NEON 编译
- 🎯 **理想**: tick < **31µs**（预算 50%，留系统/CNN 余量）
- ⚠️ **降配可救**: 超预算 → L512 / 关在线Ŝ / 关反馈抵消，每项对半砍

## 2. 带宽预算（真实瓶颈，非 DRAM 容量问题）

### 2.1 工作集 vs 缓存

| 数组 | 大小 |
|---|---|
| xd（E×S×L×4B） | 256KB |
| Ŝ / sec_coeffs（E×S×SEC_LEN×4B） | 256KB |
| Wc（S×L×4B） | 32KB |
| **合计** | **544KB** |
| RK3568 L3（对核呈现 L2，共享） | **512KB** |
| 每核 L1D | 32KB |

**关键**: 工作集 544KB **恰好超过** RK3568 全部 512KB L3 → 必然有部分驻留 DRAM，且 CNN/系统进程会抢缓存。

### 2.2 每样本访问量（开Ŝ）

| 访问 | 大小/样本 |
|---|---|
| xd 读 2 遍（功率+梯度） | 512KB |
| Ŝ 读（Fx）+ 在线Ŝ（读2+写1） | 1,024KB |
| Wc 读写 | 64KB |
| **合计** | **~1.6MB/样本** |

### 2.3 DRAM 流量（只算 L3 溢出部分）

- 假设 L3 命中率 50-80%（544KB 工作集顶在 512KB 边上，实际偏保守）
- 落到 DRAM：1.6MB × ~30% × 16k ≈ **~7.7GB/s** → 接近 RK3568 6.4GB/s 理论上限 ⚠️
- L=512 或关在线Ŝ：工作集减半，DRAM 流量 ~3.8GB/s → **余量充足** ✅

### 2.4 带宽验收线

- ✅ **达标**: 持续实测吞吐 ≥ 6 GMAC/s，无 xrun/爆音
- ⚠️ **风险点**: 8×8+L1024+开Ŝ 全开 = 工作集 544KB 顶爆 512KB L3 → **必须降一项**（L512 或关Ŝ）
- 换 RK3588（3MB L3 + A76 私有 L2）→ 此项直接解锁

## 3. Preview / 因果预算（1m 参考麦）

### 3.1 公式

```
preview = 参考→误差声学延迟 − (codec ADC+DAC 延迟 + DSP 处理延迟 + 扬声器→误差声学延迟)
```

### 3.2 1m 的账（声速 343m/s）

| 分量 | 低延迟 codec | 通用 codec |
|---|---|---|
| 参考→误差（1m） | **+2.92ms** | +2.92ms |
| codec ADC+DAC | −40~100µs | −1.0~3.5ms |
| DSP（逐样本流水线，算力够则≈0） | ~0 | ~0 |
| 扬声器→误差（0.2-0.5m） | −0.6~1.5ms | −0.6~1.5ms |
| **净 preview** | **+1.3~2.3ms ✅** | **−0.2~−2.2ms ❌** |

### 3.3 结论

- **1m 参考距离本身足够**：2.92ms 是白送的提前量，等于 46.7 样本缓冲
- **通用 codec 是凶手**：1-3.5ms 的 ADC/DAC 转换延迟直接吃光 1m 的全部 preview → **低延迟 codec 是硬前提**
- **扬声器布局**：扬声器离误差麦越近越好（0.2-0.5m），否则它消耗 preview

### 3.4 Preview 验收线

- ✅ **达标**: 实测环路延迟（参考麦采样→anti 出扬声器）< **2.5ms**，低延迟 codec
- 🎯 **理想**: < 2.0ms，扬声器贴窗面布置
- ⚠️ 实测方法: 注入脉冲，测参考→误差传播总时间

## 4. 相干性预算（1m 的预测能力，需实测）

### 4.1 物理本质

相干性回答"参考麦信号能否预测误差麦信号"。失相关来源: 湍流、多径反射、空间非均匀。**它与算力无关**——相干性不够，再快也消不掉。

### 4.2 各种估计（同一个 1m，结论差 2 倍）

| 模型 | 1m 相干上限 | 说明 |
|---|---|---|
| 自由场平面波（无湍流/反射） | 无上限 | 参考=纯延迟，相干=1 |
| 工程经验 c/d（历史文档用） | ~343Hz | 偏乐观经验值，非定律 |
| 混响场 sinc 模型 | ~171Hz | 偏悲观 |

**c/d = 343Hz 不是严格物理定律**——它是环境相关经验估计，且没区分"窗外干净参考" vs "室内多径"。

### 4.3 实证对照（Lam 2020, Sci Rep）

- 窗外参考麦 + 窗内误差区（1m 级距离）+ 24 扬声器
- **300-1000Hz 中频实测 7-10dB** → 证明 1m 级距离下中频相干性**够用**
- 但那是干净窗外参考 + 全窗阵列；**多径混响强的室内单点参考麦**在 500Hz 相干性确实有下降风险

### 4.4 结论

- **1m 相干性不是公式能判死刑的**——"500Hz 必死"是过度简化
- 窗外干净参考 + 参考麦贴窗面（<50cm，相干上限 ~686Hz）→ 500Hz 安全
- 多径室内 + 单点参考 1m → 500Hz 有风险，**上参考阵列**补高频相干
- **定性: Phase-1.5 阻塞项，必须现场实测，不能靠 c/d 公式定论**

### 4.5 相干性验收线

- ✅ **达标**: 500Hz 参考-误差**实测相干度 ≥ 0.8**，且纯音对消 ≥ 10dB
- ⚠️ 未达标: 参考麦移窗面（<50cm）或上参考阵列，重测

## 5. 验收总表（上板后逐项打勾）

| # | 项 | 达标线 | 不达标对策 |
|---|---|---|---|
| 1 | 算力 | 8×8+L1024 tick < 62.5µs | L512 / 关在线Ŝ / RK3588 |
| 2 | 带宽 | 持续 ≥6 GMAC/s 无 xrun | 降 L / 关Ŝ / RK3588 |
| 3 | Preview | 环路延迟 < 2.5ms | 低延迟 codec / 扬声器贴窗 |
| 4 | 相干性 | 500Hz 相干 ≥0.8 | 参考麦 <50cm / 参考阵列 |
| 5 | codec | ADC+DAC ≤ 100µs | 换 ANC 级 codec |

**四层结论一句话**: 算力=NEON+降配可救，带宽=工作集顶爆 L3 需降一项，preview=低延迟 codec 决定，相干性=实测决定（1m 因果够、相干需验）。
